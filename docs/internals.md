# Firmware internals

How the scroll-wheel payload hooks the stock Shanling Q2 firmware. For the user-facing behavior it produces, see the [README](../README.md); build and release steps are in [building.md](building.md) and [releasing.md](releasing.md).

`release/bin/demo`, `usr/bin/hciplayer` (the PEQ filter, one branch, [Large MP3s](#large-mp3s), two calls, [MP3 ReplayGain](#mp3-replaygain), and the MQA gate and probe length, [MQA detection](#mqa-detection)), `usr/bin/bluealsa` (AAC capability and Bluetooth DROP handling), `usr/bin/checkappprocess.sh` (one sleep, [Battery](#battery)), the boot logo, `home_page.bin` (the Coverflow card; the iPod Home list) and the artist page inside `rootfs.squashfs` change, and the stock EQ preset page and the images only the stock EQ pages show (`STOCK_EQ` in `tools/build.py`) are removed. iPod additionally changes the other audited assets in `patch/ipod.json`: local browsing, settings and streaming pages, the equalizer page, the status bar, Now Playing and the theme (`styles/default.bin`). It also removes the 14 carousel images (`CAROUSEL`) and does not add the Coverflow card icons. The build adds `usr/bin/q2video` ([Videos](#videos)), the new Local Music icons and Streaming's Spotify icon. The kernel is byte-identical, and the builder checks every other inode's name, type, mtime, mode, uid and gid against stock.

## Hooks

Checked MIPS prologues redirect into a payload at `0xb00000`, using the final unused `PT_NULL` program header. demo's `.pdr` section, outside every segment, is zeroed for rootfs space ([building.md](building.md)). Trampolines restore the stock GOT base and resume each original function after its PIC setup. Writable input and position state is mapped at `0xb50000`, a `NOLOAD` section: the segment's memory size covers it, the file does not.

`HOOKS` and the `WM_PAINT_LEAF` in `tools/build.py` are hooked in both variants; `IPOD_HOOKS` and the `IPOD_LEAF` only in iPod, so the Legacy build keeps those entry points stock.

The manifest's `compact_code` lists every changed word.

Stock V1.32 turns the touch wheel into key events 172/173: the encoder thread (`0x6258e0`, unnamed in the symbol table, after `encoderknob_thread_run` at `0x6256a0`) reads tslib samples (x, 1-200 a turn, and pressure) and calls `get_direction` (`0x62587c`), but only once per 80 ms gate (200 ms after touching), at most one tick per look, dropping any travel past its threshold. On the device that cost more than half the travel (27 units per tick against a threshold of 12), a single tick for a fast half turn and nothing in a touch's first 200 ms. So the build replaces the tick logic: the thread's `ts_read` call (`WHEEL_TS_READ` in `tools/build.py`) goes through `ringnav_ts_read`, and `wheel_sample` (`patch/playback.c`) makes a tick of every `WHEEL_TICK_UNITS` (28, a seventh of a turn) of travel at the default Wheel Sensitivity (below), carrying the rest; a reversal starts the count again and a lift drops it. It posts each tick with stock's poster (`WHEEL_POST`, `0x6257f0`) as a key-down (`0x110`) then a key-up (`0x114`), and hands stock the touch-down x, so stock's own logic sees a still finger and posts nothing. The payload moves on the release, at `on_wm_keyup_before_fun`; iPod also sees the press ([iPod row clicks](#ipod-row-clicks)). These events are not fixed physical detents. Below, a tick is one such event and a step is a row move the payload makes.

**Input queue.** The wheel, the touchscreen and the buttons all post to AWTK's main-loop queue (`main_loop_simple_init`, `0x68b70c`: `event_queue_create(20)` at `loop+0x38`), which drops its oldest event when full. A tick is two events, so a fast turn while the UI was busy could evict a touch's release: the window manager then kept the pointer pressed (a row stuck in its pressed shade), and `ringnav` dropped every tick until the next tap. `wheel_post` reads the queue's `r`, `w`, `full` and `capacity` (unlocked; off by one at worst) through the poster's main loop (`WHEEL_INFO_LOOP`, `LOOP_QUEUE`) and drops a tick that would leave fewer than `WHEEL_QUEUE_FREE` (8) slots, so a busy UI loses ticks it could not have shown yet instead of a touch or a key, and nothing replays later. Checks in `test/playback.py`.

Stock drops wheel ticks for 800 ms after Centre or Return (`KEY_LOCKOUT`, 8, counted down per 100 ms) so a press that brushes the wheel does not scroll; `ringnav()` keeps only its first `LOCKOUT_KEEP` (2) x 100 ms. A tick that lands while a page slides, or before the new page's list loads, is held (`hold_wheel`) instead of dropped: up to `HOLD_MAX` (8) of them, a reversal cancelling, play into the page one per `HOLD_POLL_MS` (16 ms) once it is ready, unless Centre or Return comes first or `HOLD_MS` (1.2 s) passes. So a turn begun on Back or Select carries on into the page.

**Wheel Sensitivity.** **System settings → Display → Wheel Sensitivity**, the last row in both builds (`ringnav_display`, the `system_display` icon), reads `Wheel Sensitivity: 50%` and sets the travel per tick: 50-200% in tens, `WHEEL_TICK_UNITS` x 50 / sensitivity, so 50% is 28 units, 100% 14, 130% 10.75, 150% 9.3 and 200% 7 (3.5 to 14 ticks a turn). `wheel_sample` counts in sixteenths of a unit (`WHEEL_FINE`), so the carry keeps the fraction and every step differs. It is `Q2POD WHEELSENSITIVITY` in `config.ini`, read on the first UI pass (`playback_poll` calls `wheel_pct`); a missing key or anything but a canonical ten in 50-200 is 50%. That is 1.0.6's key and scale (1.0.6 rounded the travel to whole units), so a value saved in 1.0.6 comes back as it was. A value saved before 1.0.6 comes back with the same label but about twice its old speed: the old engine's threshold scaled the same way but lost about half the travel to stock's 80 ms gate (27 units a tick at 100%), so its 100% felt like today's 50%. 1.0.7 removed the setting (fixed at 28) after 1.0.6 had kept those pre-1.0.6 values under the new meaning. `wheel_units` is one word the UI thread writes and the encoder thread reads, 0 until read, which `wheel_sample` takes as 50%. A change applies on the next sample: when the travel changes mid-turn, the carry is scaled to keep its share of a tick (`wh_acc * new / old`), so it stays under the new travel and fires no burst. Only the travel changes: `LOCKOUT_KEEP`, `hold_wheel`, the list and scrub ramps (`WHEEL_RUN_MS`, `WHEEL_RAMP_MS`, `LIST_FIRST_MS`) and every consumer (rows, volume including screen-off, scrub, `LYRIC_STEP`, Coverflow, Books, Videos) count ticks and time, so they just get more or fewer ticks a turn. The row opens [Crossfade](#crossfade)'s re-dressed Boot volume page (`xfade_open` with a nonzero context, `xf.wheel` in `patch/crossfade.c`): titled Wheel Sensitivity, the switch hidden, its slider 50-200 in steps of 10 (a drag snaps to the nearest ten), +/- and the wheel a ten a tick (`xfade_key`), and Centre going back as on Brightness (`edit_key`). Each change is saved with `write_int_config` and the Display row's label (named `label_wheel`) follows.

## Supported screens and panes

Navigation requires a supported top-window name from `patch/contexts.inc`, screen-on and no lock/test/guide/power-off/USB-link/Bluetooth-receive screen, and a navigable pane: a vertical `scroll_view`, a `table_client`, a `slide_menu` or, in iPod, a dialog or page flagged `BUTTONS`, whose buttons are its rows and which never scrolls ([ipod.md](ipod.md#pop-ups)). Horizontal and page-snapping scroll views are not candidates, so they cannot make a page look like it has two panes. When two panes are visible and neither owns the selection, the first wheel turn chooses the first pane in UI order. Later turns follow the selected pane, and tapping a row switches ownership. If both panes already hold a selection, the wheel event is left alone. Only active `pages` children are searched. The bounded walk collects at most 512 targets in a non-virtual list; virtual music tables navigate by total logical row count instead.

A native click chooses its pane from the actual target before walking up to the nearest collected ancestor. A successful selection clears the other pane’s selection and invalidates both panes, so the drawn selection, wheel and centre follow the row that owns the tap. Hidden, disabled and inactive-page panes remain excluded.

## Selection

Selection is stored in widget-owned integer properties on the navigation surface, independently of AWTK's focused flag. The drawn selection (outline or bar) and centre action resolve that same logical selection against the current entries. Centre dispatches a synchronous native `EVT_CLICK`, so a queued click cannot hit a row rebound between selection and delivery. It never dereferences the target after delivery.

## Wheel movement

Lists with at most `SHORT_LIST_MAX` (16) logical entries always move one row per step. Virtual tables use their total logical count, not the recycled row pool size. Longer lists use a continuous ramp: a same-direction tick spaced at most `WHEEL_RUN_MS` (140 ms) from the previous one extends a spin run, and the step grows with the run's duration, capped at `WHEEL_MAX_STEP` (8) rows. It is a duration ramp, not a measure of the wheel's angular speed. `ramp()` takes the curve from its caller:

| Caller                                                              | One row while the run is under | Then                                      | Eight rows from |
| ------------------------------------------------------------------- | ------------------------------ | ----------------------------------------- | --------------- |
| Legacy build; iPod's pixel-scroll fallback and [scrub](#scrub-ipod) | `WHEEL_RAMP_MS` (100 ms)       | `1 + run / WHEEL_RAMP_MS`                 | 700 ms          |
| iPod row lists and button dialogs                                   | `LIST_FIRST_MS` (300 ms)       | `2 + (run - 300) / LIST_RAMP_MS` (200 ms) | 1500 ms         |

The pixel-scroll fallback is a pane without clickable rows, which scrolls `RING_STEP` pixels per step. A pause, reversal, touch, native click, centre press, list boundary or rejected navigation resets the run. Acceleration belongs to the current window, pane and browsing scope; a list resize also resets it.

Wheel movement cancels existing momentum and uses the stock `scroll_view_set_offset` / `table_client_set_yoffset` setters immediately, reloading table row references after synchronous rebinding. Each wheel step then dispatches `EVT_SCROLL_END` (`0x14f`), which touch momentum sends when it settles: the setters send only `0x14e`, which the album page takes as pause, and stock lists queue their visible covers on scroll end (album page `0x4a440c`). Remembered-position restoration retains its separate glide. This follows the row-based approach of Rockbox's [H2/Eros Q wheel mapping](https://github.com/Rockbox/rockbox/blob/master/apps/keymaps/keymap-erosq.c) and [list implementation](https://github.com/Rockbox/rockbox/blob/master/apps/gui/list.c).

Selected and restored rows use a `SCROLL_MARGIN` of 12 pixels above and below, reduced to half the spare viewport height in tight lists and clamped at content boundaries. Rows taller than the viewport align their top edge when selected or restored, keeping their title visible.

## List ends

The local file and music lists carry over at their ends; `patch/contexts.inc` marks those audited row lists with `ring`, and iPod Home does too, while grids such as `album_page`, settings menus, dynamic pages, and the Stock build's Home carousel keep hard ends. The first tick past an end nudges only the drawn selection by `BUMP_PX` for `BUMP_MS`, without moving the viewport. Further ticks hard-stop there, bumping again, while the wheel keeps turning: each one re-arms. Only the first same-direction tick at least `EDGE_PAUSE_MS` (300 ms) after the last stopped one selects the opposite end of the same list and reveals it immediately. The existing boundary rule already reset the spin run, so the wrap lands at one row per tick. The arm is cleared by a move off the boundary row, a reversal, touch, a native click or a centre press.

Every tick against an end bumps and re-arms, so the pause is measured between ticks. Reaching an end, a bump and the wrap end the run and leave no speed; the next tick is a first one.

## Key Tone

The click is the MCU's buzzer, the device's own speaker: `buzzeer_switch` (`0x4f3cc8`) runs `system("cmd_mcu write_str buzzer")` when the byte `g_keytone_flag` (`0xa38c31`, the Key Tone setting) is set, and nothing else; stock sends it whatever plays and whatever is plugged in. Both builds hook it (`ringnav_buzzer`, stock resumed at `0x4f3cd4`), so every click, stock's three call sites and the iPod row click below, passes one gate: none while headphones or another output listen: either jack (`g_po_status` `0xa38af3`, 3.5 mm, GPIO `PA07`; `g_bal_status` `0xa38af2`, 4.4 mm, `PA08`; 1 plugged, kept by `check_headset_status` at `0x4e8e14`) or an output way other than the DAC (`mclGetOutputWay`, `0x5ac484`: 1 Bluetooth, 2 USB DAC, as `config_outputchannel` sets it). Otherwise stock runs, so with nothing plugged in the buzzer clicks as before, music playing or not, and Key Tone off is still silent. There is no headphone click: a paused hciplayer keeps its PCM (`hw:1,0`, or `bluealsa`, one client per PCM, no `dmix`) open and stock's pause mutes the DAC (`mclSetMute`, `player_play_pause` `0x5157d8`), so a click has no free output; silence is the fallback, never the speaker.

### Wake

**System settings → Power → Wake** (`Q2POD WAKEDOUBLE`, read with Charge Limit and Low Power). With it on and the screen off (`g_backlight_status` clear), `wake_gate` in `ringnav_input` (`window_manager_dispatch_input_event`, before the window manager and every key hook) drops a centre (218, the power key) `EVT_KEY_DOWN` (`0x110`, as `widget_on_keydown` tests at `0x6627c4`; `0x111` is its long press) and its release, and records the press. A second press within `WAKE_MS` (500 ms, looser than `DOUBLE_CLICK_MS` since it is done blind) passes, press and release, so stock wakes the screen on it, and holding that accepted press still reaches stock's long-press power-off. Return (170) is dropped while dark in either mode, press, long press (`0x111`) and release, so a bump of Back leaves the page alone. Every other key passes, so the wheel's volume, the media buttons and Spotify's keys work dark; with the screen on nothing is touched and a pending pass is cleared, and with the setting off a centre press passes at once. Another centre press within `WAKE_MS` of the one that woke the screen (`woke_at`, either mode), or of the first UI loop pass with the screen lit (`ringnav_sleep` restarts `woke_at` then), is dropped with its release (`wake_eat`), the blind double press's window: turning the screen on (stock's `on_wm_keyup_fun`) and that pass's paint stall the loop about that long, and `wake_gate` times presses as they are dispatched, so a second press made during the stall arrives after it. So a quick double press from dark only wakes: it neither clicks the selected row nor, as a screen-on double press, turns the screen straight off. Centre's repeated downs (first at about 258 ms, then every 50 ms) share their original press's fate, so holding a waking press keeps the release that lights the screen. A dropped press stays dropped with its repeats and release; holding it does not add a wake gesture. A passing hold keeps stock's long-press power-off. AWTK generates the long event downstream of this input hook. Stock's Standby (`check_to_poweroption` calls `device_standby`, `0x4f7a2c`, which suspends in `toolsIntoStandby`) wakes the screen once any key resumes it, a `bal awake_screen` (`0x4f7d24`) whatever the key; that call becomes `li $v0, 1`, skipping it in both modes, so the resuming key acts as it does dark: Play/Pause plays, a centre press wakes (Single Press) or counts as the first of two (Double Press). Stock then sets `BOOT_KEY_GUARD` (`0xa37c8a`), which drops the next centre release so the resuming press cannot turn the screen straight off again; the first centre down while dark consumes it and resets held-key tracking, so repeats keep that press's fate even if Standby lost the preceding release.

### Volume guard

**System settings → Power → Volume Guard** (`Q2POD VOLGUARD`, off by default, read with Wake into `wheel_guard` in `patch/playback.c`), against pocket brushes moving the volume (#46). With it on and the screen off, `wheel_sample` (the encoder thread, before any tick is posted) counts a touch's travel one way in `wh_guard`, in sixteenths of a unit, and posts no tick until `WHEEL_DARK_GUARD` units (100, half a turn of the 200-unit wheel, whatever Wheel Sensitivity is). That travel is dropped, the dead zone, and the tick carry starts from zero there. The wheel is then open: it ticks as lit, reversals and new touches included, until it has gone `WHEEL_DARK_IDLE_MS` (1.5 s, `time_now_ms`) without travel. A reversal, a lift or that pause before the guard is passed starts the count again, and so does the screen coming on, where the wheel is never guarded. Nothing is held for later, so `hold_wheel`, the volume overlay and Bluetooth volume see only the ticks that pass; with the setting off the dark wheel is stock's. Both constants are in `patch/offsets.inc`.

### iPod row clicks

Stock clicks on the press. `on_wm_keydown_before_fun` (`0x4e8424`) calls `buzzeer_switch` (the exported spelling; its only three call sites). A latch (`0xa37c90`), set after the call and cleared by `on_wm_keyup_before_fun`, keeps it to one click a press. Every wheel tick is a press and a release, so stock clicks on every tick, whether or not a row moves.

iPod hooks that callback (`ringnav_keydown`, stock resumed at `0x4e8430`). For a wheel press that the release will take as row navigation it saves `g_keytone_flag`, clears it, runs the whole stock body and restores the byte before returning stock's result: the power timer, the lock gates and both latches run as stock, and only the click is missing. Besides `buzzeer_switch`, the byte is read by `config_init` and by the System settings page's Key Tone row and its click handler (`0x4cc0a0`, `0x4cc2dc`), all on the UI thread, and the stock body calls nothing back into the UI, so nothing else sees it cleared. Whether a press is such a press is decided from the widget tree alone (screen usable, a `contexts.inc` window, a pane that is not a `slide_menu` and holds a clickable row); nothing is loaded, selected or restored. Every other press runs stock unchanged: the buttons, the volume, scrub, carousels and other slide menus, the pixel-scroll fallback, and the wheel while the screen is off or locked.

The press leaves its key in `tone_key`. Every key-down rewrites it and every key-up clears it, so a dropped release cannot carry it into a later input. On the release, `ringnav()` calls `buzzeer_switch(1)` once when that tick's step changes the selected row, with the setting as it is then: one click for a step of any size and for a wrap (a held tick's replay included), and none for a hard end, a bump, a rejected tick (a pointer down, stock's wheel lockout after a button) or a release whose press stock already clicked. If the page stops being a list between the press and the release, that tick is silent and the next press is stock's again. The call is in the wheel path, not in `select()` or the paint hooks, which also run for restoration, touch and repaints. The Stock build has no key-down hook and clicks as stock.

## Scrollbar

Wheel motion also wakes the native scrollbar of the controlled surface. `native_scrollbar()` finds the surface's `scroll_bar_m` sibling under its `list_view` or `table_view` parent and calls the stock `scroll_bar_scroll_to` with the bar's current value; the stock bar keeps ownership of the thumb value and runs its own show, wait and fade lifecycle. An initially transparent bar is still woken, and a surface without a native bar is unchanged. The payload retains no bar pointer and no fade timer, so page destruction and widget recycling need no extra handling. The end bump's `fx_token` widget property and its `fx_expire` timer remain separate from scrollbar visibility: the token rejects a recycled surface, and the timer repaints the selection at the `BUMP_MS` (120 ms) deadline.

## Centre button

A centre release arms a stock UI timer for `DOUBLE_CLICK_MS` (250 ms). A second release before expiry on the same live selection cancels confirmation and passes through the stock downstream key-up handler to turn the screen off. On a listed page where no row confirmation is pending (an empty list, nothing selected, a page still sliding in, the Books reader whose Centre is its caption), `ringnav` times the presses itself (`dc_top`, `dc_at`): a second within `DOUBLE_CLICK_MS` on the same window replays the release to `on_wm_keyup_fun`, so a double press turns the screen off on every page. Videos keep Centre for seeking. A single release dispatches exactly one synchronous click at expiry. Stock's key-up filter rejects wheel releases while a centre-key lockout (`KEY_LOCKOUT`, `0xa37c89`) is non-zero: the centre key sets it to 8 and `on_wm_timer_setup_state` counts it down every 100 ms, so a page opened by the centre button would ignore the wheel for up to 800 ms. The click clears it just before dispatch, so the opened page scrolls at once; a double press keeps stock's lockout. Touch, wheel input and invalid navigation state cancel pending confirmation. The timer resolves the target from the live menu and requires the original window, surface, content scope, logical selection, row count and row-text identity to match. Widget-owned tokens also reject reused window/surface addresses, and an ordinary list requires the armed row widget's own token; virtual tables resolve recycled pool widgets by logical index. An overdue confirmation runs before the power and lock gates that follow it. No delayed row pointer is retained; pending state clears before dispatch. Timer allocation failure consumes the press without activating anything.

## Setting editors

Stock's setting pages without a list take the wheel and Centre themselves (`edit_key`), ahead of list navigation. **Brightness**, **Maximum volume**, **Startup volume** and **Balance** (`backlight_page`, `maxvol_page`, `bootvol_page`, `balance_page`): the wheel dispatches a click to the page's own `img_add` or `img_dec`, so each tick is one stock step with stock's limits and saving; Centre goes back. The pull-down's brightness slider (`statusbar_dialog`) has no +/-, so the wheel sets its `value` by one within its `min`/`max`, which fires stock's change callback; Centre there stays stock's. **Set date and time** (`manualtime_page`: year, month, day, hour, minute) and the **sleep timer** (`sleepshutdown_page`: hour, minute) edit one `text_selector` at a time, framed in two white pixels by the border hook: the wheel steps its selected index (`SELECTOR_INDEX`, set through stock `text_selector_set_selected_index`) within `text_selector_count_options`, Centre moves to the next field, switching the date page's `slide_view` to the time page after the day, then to OK (`btn_enter`), drawn while it is next as a selected row (Minimal's off-white `MINIMAL_FILL` card, `SEL_RADIUS` corners, its label dark at `EDIT_OK_PX`) rather than framed, which the next Centre clicks; a turn on OK goes back to the last field (Previous) or the first (Next). A swipe between the date and time pages moves the field to that page's first. Centre waits `DOUBLE_CLICK_MS` (`center_press`) and clears `KEY_LOCKOUT` as a list's click does, and a double press is stock's screen toggle. The field lives in the page's `_edit_field` property, so it dies with the page.

Pickers flagged `CHOICE` in `patch/contexts.inc` (Play mode, Filter, Language, Sort and the like) open on the row holding stock's `select` check image instead of the remembered position, so the bar starts on the current setting. In Minimal, stock's white radio images (`select`, `unselect`) would vanish on the selected row's off-white card, so the border hook draws them again over it in the card's dark ink (`paint_radio`): the 26-pixel ring and, when checked, the 12-pixel dot.

USB mode's exit asks whether to scan for music in a `confirminfo_dialog` before it clears `g_usblink_status`; with the cable already out (`g_usbdet_value` 0), that prompt alone counts as usable, so its buttons take the wheel and Centre.

## Queue menu

Holding Play/Pause (key 171) fires the stock long press, 1000 ms, once per press: `input_device_status` (`wm+0x98`, via `window_manager_get_input_device_status` at `0x66e734`) dispatches `0x111` to the window manager, where stock `on_wm_keylong_fun` has no action for 171. `ringnav_keylong` takes it only with the navigation gates, AirPlay off (`airplayGetFlag() != 2`), no batch-select mode (`g_navbar_status`) and the row a centre press would open, on a `CTX_LOCAL`/`CTX_FOLDER` page, an artist's page (`artistinfo_page`, whose tabs fill the showlist) included. There the row's class is `g_local_classinfo_save+0`, which its tabs' `load_localartist_list` sets (`0xff07` songs, `0xff01` albums); `g_class_type` keeps the class the page opened or was last returned to with. The page's row count must equal `deque_size(*p_deque_showlist)`: these lists bind row _i_ to showlist record _i_ (Local Songs `table_row_of` → `deque_at` at `0x4a8838`), and a grid or extra clickable row fails the check. Everything else tail-calls the stock body.

The release still reaches `playpause_quick_click` (`on_wm_keyup_fun` `0x4e8b7c`), which has no long-press check. The hold stores the key record's u64 press time (record `+8`; 16 records of `0x18` from `+0x30`); the key-up hook swallows a Play/Pause release carrying that time and clears the latch on every Play/Pause release. AWTK drops the release when it aborts pressed keys on a window change; a later press has a new time, so a stale latch cannot eat it.

The target is the showlist index plus hashes of the record strings (`+8` name, `+0xc` path, `+0x10`, `+0x14` album, `+0x18` artist) and of the browsing state (`g_folder_path`, `g_class_type`, `g_local_classinfo_save`, `g_artist_type`); the dialog open and the action both re-check it. A type-8 record is one song. In `g_class_type` `0xf003` a row is an album: `getMusicByAlbum(id == -1 ? NULL : album)`, as `load_album_detaillist` → `load_localclass_list(0xff10)` does. In `0xff01` (an artist's albums) it is `getMusicByAlbumAndAlbumSonger` when `g_artist_type == 1`, otherwise `getMusicByAlbumAndSonger`, with `(album, classinfo[0xa] ? NULL : artist, id == -2)` (`0xff11`). A composer's (`0xff02`) or genre's (`0xff03`) albums use `getMusicByAlbumAndComposer`/`getMusicByAlbumAndGenre` with `+0x20` composer or `+0x1c` genre and `classinfo[0xb]`/`[0xc]`. An artist row (`0xf004`) is `getMusicBySonger(+0x18)`, or `getMusicByAlbumArtist` when `g_artist_type == 1`; a composer (`0xf005`) `getMusicByComposer(+0x20)`, a genre (`0xf006`) `getMusicByGenre(+0x1c)`; an id of -1 (Unknown) passes NULL. These are the expansions `batch_add_file` (`0x4f4be8`) runs for each class. A folder row (type 4) calls `toolsLoadDirectory(g_folder_path + "/" + name)` like `folder_enter`. Queries fill `tools_pdeq_directory`; its type-8 records join in order and the staging deque is restored.

Coverflow album holds resolve the live `SLIDE_INDEX` against the current sorted album deque, without opening its tracks. Sort, Refresh, preparation, empty screens and pending screen changes are excluded. Both the deferred open and action revalidate the selected record. Play Next, Add to Queue and Shuffle use `coverflow_album_tracks`, shared with opening an album, so disc/track/path/CUE ordering and staging restoration are identical. Go to Artist is available when the album has an artist; playlist actions remain omitted.

The menu is the stock `dialog/sortselect_dialog`: its init is synchronous and clears `to_modal`, so `navigator_to` returns with it on top, and it is already a navigation context. The payload replaces its five sort rows with the row's own, titles it with the item (a song by its title tag, the player's parsed title while it plays an untagged folder record, else its file name less the extension), and swaps its key-up (`0x49f3e0`) and back arrow (`0x49f3c0`) handlers, both of which set `g_sort_changeflag`, which makes Local Songs reload and scroll to the top on return. The open is deferred out of the long-press dispatch and the action out of the row click; the result is a stock `dialog/msginfo_dialog` toast (`{1, 2000, text}`).

The rows are stock actions. Every row has Play Next and Add to Queue. A song (and a Coverflow track) adds or removes a favourite, labelled from `checkFavExist`, as Now Playing's heart (`manage_myfav`): Add selects the row alone in the batch record (`batch_init_selectrecord(rows)`, `batch_set_selectitem(index)`, as `player_addplayList` does) and runs batch-select's Add to My Fav, `batch_add_file(class, 0xf00a, list, *p_vector_select_record, 0)`, which reads a folder file's tags first; Coverflow passes its own deque as class `0xf001`. Remove is `deleteMusicFromFav`, and on My Fav (`0xf00a`) it sets `g_delete_flag` so the list reloads, as the heart does. Albums, artists, composers, genres and folders get Shuffle instead: their songs, the play mode saved as shuffle, from a random song, as Shuffle Songs. Everything but Coverflow gets Add to Playlist: the row selected the same way, then `localmusic/playlist_page` with context `1 << 16 | class`, the page's add mode, whose pick runs `batch_add_file(class, 0xf00b, showlist, ...)` for the playlist and shows its own toast. A song gets Go to Album and a song or a row of all albums Go to Artist, when the record has one: Now Playing More's Album info (`0x5283b0`: `classinfo` `+0` = `0xff10`, `+9` = 0, `+0xd` album, `+0x10d` artist, then `playerjumpinfo_page`) and Artist info (`localmusic/artistinfo_page` with `{class, record}`). Both pages reload from `g_local_classinfo_save`, and so do the pages underneath when they come back, so the payload copies it before and writes it back on the opened page's `EVT_WINDOW_CLOSE`. Go to Album is left out on an album's own list (`0xff1x`) and either is left out while its page is already open (`navigator_window_is_exist`): both keep single-instance state, which stock's More closes first. Now Playing keeps its stock heart and More page; Photos, Books and Videos have no menu.

The queue is `*mcl_pdeqplaylist` (`0xa269a4`) with static state at `0xa3bdb0` (shuffle pool, a deque of unplayed indices), `0xa3be90` (shuffle previous index), `0xa3be94`/`0xa3be98` (gapless preloaded index/flag), `0xa3bea0` (queue class), `0xa3bea4` (position), `0xa3bea8` (mode) and `0xa3beb4` (player socket). Only a local queue (class 1 or `0xfxxx`) grows. An empty queue is loaded by `mclLoadPlayList(tracks, 0, class)`, which does not start playback. Otherwise Add appends with `_deque_push_back` and Play Next rebuilds the deque with the tracks at position+1 (`deque_clear` + `deque_assign`, as stock loads it). Pool entries and the previous index at or after the insert shift, and the new indices join the pool. Gapless preloads only pos+1 (modes 0 and 3), so a set preload flag is closed exactly when the tracks land there, with the `mclSetPlayMode` sequence (`{mcl-closegapless\null}` to the socket, flag -1). In shuffle the checked call at `0x5addf0` in `mclNextSong` (`bal 0x5a8120`, delay slot `a0 = 1`) becomes `jal ringnav_shuffle`: it runs the stock pick, then makes the first Play Next track the position once, if the queue still holds it there. Repeat-one repeats the current track by design.

Now Playing holds capture the queue pointer, length, index, song identity (including CUE offsets) and an ordered queue hash. Deferred opening and actions revalidate this target. View Queue opens stock's `playerqueue_page` after closing the hold dialog, so its rows track the live playing queue. In list order, not play order, so while advanced shuffle is on the hold also offers **Up Next** (`upnext_page`, `playback_upcoming`): the successor walk of the shuffle's order, as a snapshot. A View Queue row plays through stock's `player_start_queue` (`0x5160dc`, which `mclSetPlayPos`es and starts the player); an Up Next row calls it with its snapshot index and closes the page. Its hook (`ringnav_start_queue`, `patch/playback.c`) commits the pick in advanced play first, so Previous returns to it. Under Shuffle Songs it goes through Play Next's path, moving it right after the cursor, so the order carries on after it: the pick does not play again later in the pass, and the tracks it jumped stay up next. An ordered queue (or Shuffle Albums, Folders, a category) moves the cursor to it, so the tracks after it follow. A pick inside a pending Play Next keeps the rest of that range first. ponytail: Up Next's rows are indices from when it opened; a queue replaced meanwhile (a folder play's next folder) makes them name other tracks. Stock Shuffle draws each next track at random, so it has no order to list: Shuffle Songs and a collection's Shuffle save stock's Shuffle mode, then hand the loaded queue to advanced Shuffle Songs with Repeat All (`playback_shuffle`). Playlist add mode 2 uses the playing queue; its existing row click handlers are guarded again before the stock callback, with the captured row selected. Browsing state is independent.

## Home carousel

iPod has no carousel: Home is an ordinary list ([ipod.md](ipod.md#home)) that bumps and wraps like a ring list. The Legacy build's carousel uses `HOME_SLIDE_MS` (200 ms) for isolated ticks and `HOME_FAST_SLIDE_MS` (120 ms) when consecutive same-direction ticks arrive at most `HOME_FAST_WINDOW_MS` (200 ms) apart. There is no extra home input gate; stock filtering and audible ticks stay stock-controlled. Each accepted tick retargets one animator from its live offset, extending the intended destination by one icon. Reversal discards that destination and heads toward the adjacent card in the new direction at normal speed. Stock completion handles wrapping and card selection; centre confirmation follows the intended final icon. Touch, native clicks, centre presses, leaving home and unavailable navigation reset speed tracking; wheel input cancels pending centre confirmation. Allocation failure settles on the requested icon without retaining an animator.

**Albums.** `load_localclass_list(0xf003)` (`0x5088cc`) is `getAllAlbum()` followed by `deque_assign(*p_deque_showlist, *tools_pdeq_directory)`, so the payload calls `getAllAlbum` itself and copies the staging deque instead, restoring it afterwards: no private state, and a Local Music page underneath keeps its showlist. `getAllAlbum` runs `select id,album,songer,fileurl from songtable group by album COLLATE NOCASE` on `/mnt/data/database.db` through `toolsQueryDbTable` (`0x5c8044`: the lazily opened shared handle at `0xa3bf44`, `deque_clear`, `sqlite3_exec`, then `algo_sort_if` with the stock comparator). Its row callback (`0x4fc324`) skips empty albums and fills `+0` id, `+0x10/+0x14` album, `+0x18/+0x20` artist and `+0xc` the group's `fileurl`, which is the first-track path the art build uses. When any album exists it then appends an "Unknown Album" row (id -1, no path). It returns the query count: -1 without a database, 0 when empty. That grouping is by name alone (stock's Albums list shares it), so Coverflow then runs `ALBUM_SQL`, the same columns plus `albumsonger`, grouped by album, then album artist, or for songs without one the folder (`rtrim(fileurl, replace(fileurl, '/', ''))`), through `split_row`: `album_row` on the first four columns, then the album artist into `+0x24` (`REC_ALBUM_ARTIST`), which the `stSongInfo` copy (`0x5b3b1c`) duplicates. Each stock row is replaced in place by its name's rows (`split`), one per `album_cmp` album, so same-named albums by different artists are separate covers with separate art keys; `album_cmp` tells albums apart the same way everywhere else (tracks, Sort ranks, play counts, playback's album groups). Its folder fallback takes a trailing disc folder (`CD1`, `Disc 2`, `Disk_03`: cd/disc/disk, an optional space, `_` or `-`, digits) as its parent, so an untagged multi-disc album is one; the SQL keeps disc folders apart and `split` merges them. Shuffle Folders (`folder_cmp`) keeps each folder apart. The stock Albums list gets the same split (`ringnav_localclass`), and a row's album page (`load_album_detaillist`, hooked to keep the row) and resume (`memeory_startplayer`'s 0xff10 rebuild) keep only that album's songs from `getMusicByAlbum`. Its art cache, `/mnt/mmc/.sldp/<md5 of the name>0.jpg`, adds the album artist, else the album folder, to a name that adjacent rows share (`art_key`): the row renderer (`0x4a388c`), the page's `albumcoverinfo_init` cover tasks the art thread hashes, and the album page's big cover (`0x4a72a4`). An artist's albums tab (`load_localartist_list(1)`, hooked) groups by name too, and has one row of a name another artist shares, so adjacency can't tell: `ringnav_artist_list` splits a copy of the tab as Albums is and gives each row its album's `art_key`, the same-named album in its folder, else with the row's artist as album artist. Its renderer (`0x4ab804`, the row in `$s2`) and four `albumcoverinfo_init` calls (Album tab entry `0x4ac840`, page return `0x4ae860`/`0x4ae968`, init `0x4aebc0`) use those keys, and the album page's big cover follows its cover task as before. A job finishing after navigation rebuilt the list therefore cannot mark a different album ready and make later requests skip its missing cover. When `rename_covers` changes a row's key, it clears both ready flags under the same lock, including a completion arriving between stock initialization and renaming. The grids' scroll start (`0x14e`: `0x4aab40` an artist's albums, `0x4a22b0` Library Albums) set the worker's shared `albumcover_taskstate` to 2, which it sleeps through, and their scroll end resumed it (`local_albumcover_task`) only when the first row in view changed; a wheel tick within the same rows, or the return to a scrolled grid (its `scroll_view_set_offset` sends `0x14e` alone), left every grid without art until reboot. All three stores are `nop` (`COVER_PAUSE`): the worker keeps going, and each scroll end replaces its queue as before. An artist's albums scroll end (`0x4ad878`) took its first row as `yoffset / 256 * 3`, though its rows are 160 px as Library Albums divides; it divides by 160 (`ARTIST_COVER_ROW`), so the nine covers it requests, and the renderer (`0x4ab798`) draws, are the ones in view. Coverflow keeps this order and shows the Unknown row with the placeholder, only when its card's query, `getMusicByAlbum(NULL)`, finds a song (`drop_unknown`, as [Unknown rows](#unknown-rows)): before V8.6 it showed even with every song tagged.

The copy outlives the page, because the query is the slow part of an open: `toolsQueryDbTable` sorts with a stock comparator (`0x5ba658`) that runs `utf8_to_pinyin` on both names, four `snprintf`s and several `memset`s per comparison. Only `scanAllMusicFile`, `scanSpecFolder` and `deleteMusicFromMusicDb` write `songtable` (every other `toolsInsert/Delete/UpdateDbTable` caller writes the favourites, playlist and play-record tables); their hooks step a generation before and after stock runs, and an open queries again only when the generation moved since the list was taken, or on Refresh. A list taken while a writer runs is never kept, and an empty or refused result is not kept at all.

**Folder tag refresh.** Scan specified folders keeps stock's recursive scan and cancellation, but its `toolsCheckItemExist` call (`0x5c981c`) goes through `ringnav_scan_refresh`: existing `songtable` rows re-read tags and update in place, matching filename, full path and CUE start/end. IDs, creation time and song count stay intact; a full library still refreshes existing files, while new files wait for space. CUE entries use the freshly parsed CUE metadata; ordinary files use `toolsGetMusicInfo`, including the FLAC album-artist fallback, after checking TagLib can read them. The title’s stock pinyin initial is refreshed too. SQL text is bounded and quotes apostrophes; an unreadable tag leaves the existing row intact. The existing scan writer hooks invalidate cached album groups. New songs and Update Local Music keep stock's insert path.

**Empty or scanning.** Only the modal Update Local Music dialog (`dialog_updatemusic_dialog_init`) starts the scan: `tk_thread` `wait_scan` → `scanAllMusicFile` (`toolsInitDatabase`, `toolsLoadAllFile`, commit), storing the handle at `0xa271d8` and clearing `0xa271d4`, which `wait_scan` sets when it ends. Its Back button stops the scan and quits the dialog before the thread ends. Coverflow shows "Update Local Music first" while a scan runs (handle set, flag clear) or when `getAllAlbum` returns ≤ 0, as PictureFlow's `check_database()` does. Before each folder entry `toolsLoadAllFile` (`0x5c9660`) stops the scan, as Back does, once the song count (`toolsGetMusicNum`) reaches 20,000 (`slti` at `0x5c9780`). 65,000 does not fit `slti`'s signed immediate, so its count load becomes `jal ringnav_scan_room` with the count loaded into `a0` in the delay slot (`SCAN_LIMIT`): a leaf, as the scanner keeps using `gp` after it, true below 65,000. The queue's `QUEUE_LIMIT` (65,536) already holds that many.

Coverflow's main, artist and rated views keep only albums with a track outside `/mnt/mmc/Audiobooks/` and without an `.m4b` extension, case aside (`music_albums`, `MUSIC_ALBUM_SQL`). Filtering precedes the SQL grouping so a mixed album uses a music track for its artwork. The stock library lists keep their audiobook entries.

**Tracks.** A cover opens `getMusicByAlbum(id == -1 ? NULL : album)`, which is what a stock Albums row opens (`load_localclass_list(0xff10)` with `g_local_classinfo_save+0xd`, `+9` flagging Unknown); it returns stock-ordered songs (`algo_sort_if`). The Albums list has no -2 row; that one only occurs in an artist's albums (queue menu). The result is copied out of the staging deque the same way, keeping only the cover's own album (`album_cmp`: the query matches the name alone). Coverflow then re-orders the copy into album order, disc then track then path then CUE start, so an untagged album keeps its file-name order. Its row callback (`0x4fb8b8`, `select *` from `songtable`) fills `+0x08` the file name, `+0x10` the tag's title, `+0x3c` `track` and `+0x40` `cd_num` (`REC_NAME`, `REC_TITLE`, `REC_TRACK`, `REC_DISC`). Each row shows the title tag when present, otherwise the file name less its file's extension; a CUE track's name, which does not end in it, stays whole. Folder play gets the re-ordered deque, so playback follows the list.

**Play class.** `0xff10` would resume the wrong album: memory-play re-runs `getMusicByAlbum` from `g_memory_info+0x611` (`memeory_startplayer` `0x5164e0`), which only `player_load_songlist` (`0x513634`) fills, from the live `g_local_classinfo_save`. Coverflow therefore uses folder play, `navigator_to_with_context("playing_page", {tracks, index, 1, 2})` as `startPlayFolderSong` does. `mclLoadPlayList` copies the deque synchronously, and memory-play reloads the last track's folder.

**Art.** Every stock caller holds a lock around the art calls, and none nests the two: `parse_albumcovertask_thd` (`toolsGetAlbumCover` `0x4edf18`/`0x4ef008`/`0x4ef0d0`, `toolsThumbSpecCover` `0x4ee960`/`0x4ef2d0`) and the UI-thread online thumbnails (`0x525244`/`0x52525c`) hold `parse_cover_mutex`; `player_parsecover_thd` holds `g_playcover_mutex` around `toolsGetAlbumCover` (`0x512fe0`) and `parse_cover_mutex` alone around its Tidal/Baidu downloads. `toolsGetAlbumCover` writes and removes the shared `/tmp/.tmp_picture`, so both stock threads can already race on it; Coverflow takes both locks, parse then play. `taglib_album_picture` (`libtag_c` `0x12508`) dispatches by extension to the C++ `get*_file_albumpic` helpers, none of which touches libtag_c's unlocked string list (`taglib_tag_free_strings`), which the UI thread's `toolsGetMusicInfo` uses. That list is what failed the first design; embedded art is only as concurrent as stock's own player thread already is. `toolsThumbSpecCover(src, dst, w, h)` decodes JPEG (≤ 6 MB, with libjpeg's DCT scaling for large ones) or PNG (≤ 1 MB), by their magic bytes (`toolsGetPictureInfo`), and encodes, or `cp`s a source already small enough, straight to `dst` with no extension check, so `<key>.jpg.tmp` is safe. Both return 1 on success. Stock's own cover cache (`/mnt/mmc/.sldp/<md5>{0,1}.jpg`) and folder-image finder (`toolsGetExternCover`, `0x5c49e8`) are not used: the first fills lazily as the album grid scrolls, and the spec fixes cover.jpg → folder.jpg → embedded. Coverflow tries embedded art, then `cover`/`folder` `.jpg`, `.png`, `.webp`, then ffmpeg on the embedded art (last: a process for every album without art). Whatever stock refuses (WebP, a PNG over 1 MB, a JPEG over 6 MB) goes to stock `/usr/bin/ffmpeg` (`ff_thumb`: fork and exec, its first picture or embedded `attached_pic` fitted into the box, written as a baseline 4:2:0 JPEG). ffmpeg creates the output before decoding, so a picture it can't decode leaves an empty file, even on exit 0; `ff_thumb` removes it and fails, as stock's grid cache takes any file for art. That covers the embedded picture in `build_art` and every `thumb` caller with a readable source (photos, Spotify). It writes no shared file, so it runs outside both locks. Stock's decoder also refuses palette and greyscale PNGs (its PNG reader, `0x5b66f8`, takes only colour types 2 and 6). Now Playing gets the same fallback: `player_parsecover_thd` tries `toolsGetAlbumCover` (embedded) and then `toolsGetExternCover` (folder images) under `g_playcover_mutex`, and that second call (`PLAYER_COVER`, `0x51301c`) becomes `jal coverflow_player_cover`. That runs stock's call first, then `ff_thumb` on the same `cover`/`folder` names and then on the embedded picture. It never calls `thumb`, whose `parse_cover_mutex` would nest under the player's lock in the opposite order from `build_art`'s. Folder images cost a process only when one exists. The embedded probe costs one for every track without art, so it is skipped when `g_play_id3_info` holds the track's path (`player_get_id3info` parses it before the cover thread runs) and Coverflow's cache file for those parsed tags, keyed as Home's art is, is an empty marker. ponytail: the marker records one track's result, so another disc's tracks, or tracks of a same-named album, whose only art is embedded WebP or a large PNG show none on Now Playing; tracks on albums Coverflow hasn't built, or by another artist than the album's key (compilations), still pay a probe per play. Albums already marked empty need **Refresh library**. ponytail: one process per refused cover; a resident decoder if first builds drag. Library Albums grids and Folder view get the Ogg case: `parse_albumcovertask_thd`'s three `toolsGetAlbumCover` calls (`GRID_COVER`, `0x4edf1c`/`0x4ef018`/`0x4ef0d4`: an album's cover, a folder's first track with art, a track row) become `jal coverflow_grid_cover`, stock's call and then, for an `.opus` or `.ogg` track only (stock's libtag reads no Ogg picture), `ff_thumb` under stock's `parse_cover_mutex`, which `ff_thumb` never takes, so it cannot deadlock; the lock is held for the run, as for stock's own decode. ponytail: stock caches only a hit (`.sldp`, `.downpic`), so an Ogg track without embedded art costs a process each time its row asks again, and a folder of them one per track until one has art; a miss marker if that drags.

**Build.** On open, the UI thread copies each uncached album's track path (`strdup`) and FNV key (artist, album) into a job array. One pthread then renders 160×160 art to `/mnt/mmc/.coverflow/<key>.jpg.tmp` and renames it into place. Missing art leaves an empty `<key>.jpg` marker; a track that is gone leaves nothing, so the next open retries it. There is no build below `MIN_FREE_MB` (16) free on the card (`statfs`, o32 `f_bsize` word 1, `f_bavail` word 7). Progress and the cancel flag are volatile `.scratch` ints; a 250 ms timer polls until every job is done. Cancel and window destroy join the thread, a wait bounded by one album. Refresh (the last card) unlinks the cache directory and reloads.

**Page.** The Home card clones `btn_localmusic` at index 2 in Legacy, reusing its images, and is the third row of iPod's Home list; `home_page_init`'s `widget_foreach` visitor (`0x5239b4`) binds `img_*` clicks and translates `label_*` by name and ignores unknown names. The Local Music card's label is renamed `label_library`, so it skips it too and its literal "Library" shows in every language, in both variants. The hook runs the stock init through `stock_home_trampoline` (`0x523c90`), then binds `widget_lookup(win, "img_coverflow", 1)`, whatever stock returned. In iPod it also sets up Home's art ([ipod.md](ipod.md#home)). The card opens a runtime `window_create(NULL, 0, 0, 0, 0)` named `coverflow_page`; `window_base_create` opens it through `window_manager_open_window`, and the window-manager key handlers that `home_page_init` registers route it like any page (`CTX_DYNAMIC`, exempt from the rootfs window-name check). Covers are a factory `slide_menu` of `image_create` children, each item `h` square (`0x5f3040`); with depth (below) the children stay empty and the payload draws the covers. In the flat fallback they are stock images (`image_set_draw_type` 4, as stock cover rows). `slide_menu` dispatches `EVT_VALUE_CHANGED` (`0xe`, after `0xd` will-change, `0x5f320c`) with the new index already at `+0x78`, which updates the captions; in the flat fallback only covers within ±3 then load their file, the stock way: `widget_load_image` → `image_base_set_image` → `widget_unload_image`. A failed load (the empty marker) shows `default_album_big` in Legacy or `default_album_flow` in iPod. Clicks only schedule screen changes on a 0 ms timer, so no screen change destroys the widget whose click is running. Tracks hide the covers rather than destroy them, so Return restores the album.

Coverflow’s Album and Artist sorts use the list sustained-scroll threshold to jump to the first album of the next or previous populated initial group. The active sort key skips leading articles; numeric, punctuation, separator and missing-name initials share `#`, while other Unicode initials are retained. The same carousel animator is retargeted; utility cards and wrap edges remain individual stops. The existing letter style expires after 400 ms. Recently Added, Most Played and Random keep single-album stepping.

## Sorting

Every name-sorted library list (artists, album artists, composers, genres, albums and songs: the `group by … COLLATE NOCASE` queries and `sort_first_alphabet`) is sorted in C, not SQL: `toolsQueryDbTable(…, 1)` and `toolsQueryDbTableAndSort` mode 0 pass `algo_sort_if` one of two comparators, `0x5ba658` or, with the flag at `0xa3bf4d` clear, the pinyin one `0x5b9d40`. The `ORDER BY` queries sort by time, sample rate or id, and folders sort by file name in `toolsLoadDirectory`'s own comparators. Both name comparators `snprintf` the row's `+0x10` name into a local buffer and `bal toolsTrimLeft` on it, falling back to the file name when it is empty. Those four calls (`SORT_TRIMS`) become `jal ringnav_sort_key`, which trims and then drops a leading "The ", "A " or "An " (any case) when a name follows, as Apple does; the record is untouched. "Them", "Anthrax" and a bare "The" keep their place, and equal keys ("The Cure", "Cure") stay as stock's `algo_sort_if` leaves them. Coverflow follows this order. Stock has no A–Z jump index; on a `CTX_LOCAL` page iPod's fast-scroll letter skips the same article.

## Unknown rows

## Coverflow depth

Coverflow draws its covers in software, after Rockbox PictureFlow's renderer: the selected cover faces the viewer at its native 160 pixels, two neighbours a side are turned 60 degrees inward, pushed back and dimmed, and each has a reflection. `patch/coverflow.c` owns the drawing; the stock `slide_menu` stays the navigation and animation controller, so the wheel (one retargeted animator, 200 ms or 120 ms fast, reversal), wrapping, centre, the saved album and track positions and the Refresh card all work as before. The covers are wheel-only: the `slide_menu` is insensitive, so touch neither drags nor taps them. Tunables are `CF_*` in `patch/offsets.inc`; adjust them together.

**Layout.** With depth the `slide_menu` spans the frame, 375 × 210 (`CF_VIEW_W` × `CF_VIEW_H`) at the top of the page, so every animator step invalidates all of it. Its items stay `h` square (210), and `slide_menu_set_spacer` (a store at `+0x84` and an invalidate) sets the spacer to `CF_STRIDE - 210`, so the stride that stock scroll, completion and ringnav's wheel steps use (item width plus spacer) is `CF_STRIDE` (110 px). The children are `image` widgets with no image, so stock paints nothing under the frame. The album and artist captions sit under the frame at `CF_TEXT_Y` in both builds and change on `EVT_VALUE_CHANGED`, when a move commits, never mid-move.

**Position.** `ringnav_paint`, the border hook both builds install, calls `coverflow_paint` for every widget after stock has painted it; only Coverflow's `slide_menu` on the covers screen draws. The visual position is the index less the live offset over the stride (stock completion commits `index - offset / stride`): centre album `c` and `frac`, 16.16, in `[-1/2, 1/2)`. Every cover's rotation, place, depth, brightness and reflection come from that one continuous value, so an incoming side cover unfolds into the centre as the outgoing one turns away.

**Projection.** All integer (the stock build is `-mfp64`, and integer arithmetic is also cheaper here). A cover `t` albums from the position gets a rotation that grows linearly to `CF_ANGLE` (60 degrees, a 17-entry sine table) at one album, a centre `x` that reaches `CF_X1` then steps `CF_XS` per album (quadratic up to one album, so the two covers turning mid-step keep clear of each other), a depth that reaches `CF_Z1` then `CF_ZS` per album, and a brightness of 256 at the centre, `CF_BRIGHT1` (75%) one out, `CF_BRIGHT2` (50%) two out and 0 three out, so covers fade in and out at the edge of reach. Left covers mirror right ones about the centre line (between columns 186 and 187). For each screen column the renderer inverts the perspective (eye `CF_EYE` px away) to the cover column under it and the cover's projected height there, then steps down the texture column, top and bottom rows weighted by coverage. At rest the selected cover is its texture pixel for pixel. Below each cover its reflection is the column mirrored, `CF_REFLECT` rows at native size scaled by perspective, from `CF_REFLECT_TOP` (18.75% in iPod, 25% in Stock) of its brightness down to nothing: no blur or glow.

**Compositing.** The frame is drawn nearest cover first: each pixel's alpha byte holds the coverage so far and every layer fills only what is left, which composites as drawing back to front would, and per column a span of rows known to be opaque is skipped outright, so hidden parts of side covers cost nothing. A last pass makes every pixel opaque over black. The hit test walks the same order, nearest first, over cover bodies only.

**Frame and textures.** One `bitmap_create_ex(375, 210, 1500, 1)` (RGBA8888; `bitmap_t` is 0x48 bytes, flags `u16 @0xc`, format `u16 @0xe`, buffer `@0x14`) is created with the covers and marked `BITMAP_FLAG_OPAQUE` (bit 0, as `bitmap_init_from_rgba` sets it for opaque images); `bitmap_lock_buffer_for_write`/`bitmap_unlock_buffer` bracket each render and `canvas_draw_image(canvas, bitmap, src, dst)` (`0x635254`, `dst` relative to the canvas origin, which is the `slide_menu`'s) draws it 1:1. It is re-rendered only when the position or a texture changes; a repaint in place only draws. Textures come from the existing JPEG cache: `widget_load_image`, `bitmap_lock_buffer_for_read` and `bitmap_unlock_buffer` read the decoded image (the stock loader, `stb_load_image` called with RGBA8888 for both formats at `0x6810cc`, never premultiplies), its centred square is sampled to 160 × 160 over black into the payload's own buffer, and the load is dropped at once with `widget_unload_image`, as stock cover rows do; the image manager's copy is only read. Seven slots (`CF_RING`) hold the covers within three albums of the position; as movement crosses an album the one leaving is dropped and the one entering is decoded. A small library repeats round the ring as the `slide_menu` wraps, each album decoded once. Missing art and the Refresh card use `default_album_big` in Legacy; iPod uses `default_album_flow`, a 160px copy of Home's disc resized with Lanczos at build time and decoded 1:1. Both are decoded once and left in the manager's cache as theme images. iPod clips each cover column to rounded corners at the Now Playing radius ratio (12/166), including the mirrored bottom in its reflection; the insets are computed once, with no alpha processing in the pixel loop. The frame and all eight textures (about 1.1 MB) are allocated together when the covers are built; if either fails, Coverflow keeps the flat stock covers exactly as before. Refresh and closing the page destroy the frame and free the textures.

**iPod artwork.** Home's 290px disc is the master placeholder for album rows, Now Playing, the full-screen art, the lock screen and AirPlay, pre-sized at build time to each stock asset's dimensions, keeping the disc's transparent corners so a selected row's bar shows through them (Now Playing's to the 166px art it fills; the full-screen `default_bigcover` a 320px disc centred on black). The artist-person icon keeps its stock image. Library thumbnails (`file:///mnt/mmc/.sldp/`) and stock's temporary playing covers (`coverpic.jpg`, `externpic.jpg`, `album_tidal.jpg` in `/tmp`) get rounded alpha at radius min(width, height) × 12/166 in `ringnav_image_add`, before the image manager caches them. The hook clears the cached opacity flag and keeps straight RGB, so stock can blend the corners over wallpaper or selection panels. Alpha is clamped to arc coverage, making reuse idempotent. Now Playing and Spotify also retain their 12px screen-space mask.

**Checks.** `test/coverflow.py` builds the renderer on the host and checks the selected cover pixel for pixel, that nothing is drawn outside the frame, mirror symmetry at rest and mid-turn, brightness one and two out, the reflection's rows and fade, that a small step changes little (including where the centre album changes hands), the texture window's loads and releases, the centre click, one- and two-album libraries, missing art, Refresh, return from tracks and the allocation-failure fallback; `--captures DIR` writes the renderer's frames at rest and a quarter, half and three-quarter turn as PNGs. `test/patch.py` runs the MIPS payload's renderer against the host build byte for byte, and the page's paint, centre click and fallback, and prints the payload's instructions per frame (about 3.5 million for a frame mid-turn under the mocks): a relative measure, not a frame time.

## Position memory

Position memory is a bounded 64-entry table keyed by the audited top-window context in `patch/contexts.inc` and a content fingerprint. Selecting a row updates its entry and moves it to the front; a full table evicts the least recently selected entry. Restoration alone does not promote an entry.

Local folders use the full bounded `g_folder_path`; local music lists use the stock browsing class, saved query and artist/album modes (`g_class_type`, `g_local_classinfo_save`, `g_artist_type`, `album_modetype`). Root Albums, Artists, Composers and Genres lists ignore the saved detail query: opening an artist overwrites it without changing the parent collection. These are the inputs used by the stock folder and local-list loaders, not playback metadata. The builder verifies each object's size against the stock ELF. A changed fingerprint resets selection even if a surviving surface has the same row count, then restores the matching recent position and reveals it, or keeps the stock viewport if none is remembered. Fixed settings menus can restore by window name alone; multi-pane and other dynamic pages without an audited content identity keep their live widget selection but do not restore across recreation.

Memory lasts until power-off, with no filesystem writes. The table occupies 1,280 bytes. Ordinary paints do not search it; repeated selections in the current scope match its first entry and shift nothing. Lookup and promotion are bounded by `POS_MEM` (64).

Non-virtual lists also remember hashes of the selected row's first two text values, read through the stock `widget_get_text` UTF-32 accessor. A matching second text outranks proximity; equal matches choose the occurrence nearest the remembered index. Rows without text fall back to the index within the same content scope. The stock rows expose no stable item id. Both scroll views and virtual music tables protect an interrupted recall glide from silently replacing the remembered selection with a currently visible row. A real tap cancels the glide and selects its target; a wheel step advances from the remembered logical row. Pointer-down and synchronous click delivery load rows without recall, so native touch sees the widget it pressed and a rebuilt list cannot move or rebind that row first. Synchronous table rebinds discard the old row-pool snapshot before resolving the selected entry.

## Touch mode

A session-wide touch-mode flag suppresses only custom drawing, independently of logical selection and gesture state. Touch-down and native clicks (including clicks without touch-down) set it and invalidate the visible window. It persists through settling and page changes. Accepted wheel input, including a turn at a boundary, centre selection or an accepted Return release restores drawing, so the page Return goes back to shows its row; iPod's Home list ignores the flag and always draws its bar; synchronous centre-generated clicks bypass the native-click observer.

## Drawing

The canvas hook intersects the existing clip with the viewport and restores the clip, the LCD fill color and the LCD stroke color; this firmware's `canvas_save/restore` do not save those properties. The outline is one translucent fill (`0x402b2b2b`, a per-color alpha) plus two concentric one-pixel `canvas_stroke_rounded_rect` calls, a dark separator at radius 9 and the 70%-opaque white line at radius 8, with `bg_r = NULL`. The separator is the stock dark surface at `0xb32b2b2b`, so it disappears on the dark theme and only shows over bright artwork. It never calls `canvas_set_global_alpha`, so the shared alpha is untouched. A rounded call that reports failure (either stroke) or a row too small for the corner radius, keeps the square separator-plus-white outline instead.

iPod draws a selection bar instead of the outline. `widget_paint` (`0x65f28c`) calls `widget_on_paint_background`, then the widget's own paint, its children and `widget_on_paint_border`, so the background hook paints the bar behind the rows. The border hook then draws nothing, and the selection is loaded and settled once per frame, in the background hook. The bar spans the full surface width at the selected row's height and position, including the end bump; an entry narrower than half the surface, a grid tile, gets the bar in its own rectangle. It is a flat fill drawn through the existing equal-stop painter as one-pixel `canvas_fill_rect` (`0x634ad0`) bands, which avoids the stock `gradient_t` ABI, followed by a one-pixel top highlight. In Theme: Minimal the fill is `#EEEEEC` under every accent; selected title and metadata colors are resolved from paint ancestry by `ringnav_style_color`, without mutating recycled widget styles, and Home uses a white dot instead of a bar. Theme: Classic draws the accent's top, bottom and highlight (`ACCENTS`) and leaves the ink alone ([ipod.md](ipod.md#theme)). The bar uses the same clip, color restore and touch-mode rules as the outline. Rows only show it where they are transparent: after the iPod style edits, list rows, table rows, grid tiles (`s_btn_listblack`) and the settings rows (`s_btn_listitem`) are.

The iPod border hook draws the chevrons. Windows flagged `DRILL` in `patch/contexts.inc` get the stock `list_into` image on every row, over the bar as well: `widget_load_image` (`0x65c1ec`, served from the image manager's cache) once per paint, then `canvas_draw_icon` (`0x638c9c`: canvas, bitmap, centre x, centre y, relative to the canvas origin like the fills) per row, placed as stock rows place their `img_into`: left edge `CHEVRON_W` (58) from the row's right edge, inside the same viewport clip, which hides rows outside it. A playlist button spans the same 20 to 355 pixels as a category or album button, so the glyphs cover the same screen columns (317 to 327); Local Music's own images sit 5 pixels further right at a fixed x. On a drill window the row layouter lays out as if that image were the last child, so the title and a playlist's "more" button end before it. The widget's own window, found through its parents, decides, so a window painted during a transition keeps its own rows. Rows narrower than half the surface (tiles) get none, and none are drawn while `g_navbar_status` is set, as stock hides its own chevrons in multi-select.

The iPod border hook also draws the fast-scroll letter over the list. A step of more than one row (so the list has more than `SHORT_LIST_MAX` rows and the run has reached `LIST_FIRST_MS`) restarts a one-shot `LETTER_MS` (400 ms) timer. While it runs and the spin run is still past `LIST_FIRST_MS`, the surface draws the selected row's first non-space character, past an article on a library page ([Sorting](#sorting)). The text is the row's first non-empty `widget_get_text`, taken from the same `row_id` walk as the position-memory hashes, and a virtual table finds its logical row in the recycled pool; an offscreen or textless row draws nothing. The box is `LETTER_BOX` (80) square, `canvas_fill_rounded_rect` at radius `LETTER_RADIUS` (12) in the stock dark surface at `LETTER_ALPHA` (85%), or a square fill without a vgcanvas. The glyph is `LETTER_PX` (60) in the system default font (`canvas_set_font` `0x633e6c` with a null name), white (`canvas_set_text_color` `0x633d9c`), centred by `canvas_draw_text_in_rect` (`0x639524`) with the canvas alignment fields (`+0x34` horizontal, `+0x30` vertical) set to centre and middle. The clip, fill and text colors and alignment are restored afterwards; the font is not, since stock sets it before drawing its own text. The expiry repaints the live surface, which then draws nothing.

## Accent

iPod's accent ([ipod.md](ipod.md#display-settings); Theme: Minimal uses Graphite's, whatever is stored) replaces Shanling red wherever it is drawn:
the theme's style colors, inline `style:*` colors (a mutable style answers through the same
vtable), decoded images, and the payload's own selection bar and progress fill, which read
`ACCENTS` directly. `accent_map` (`patch/navigation.c`) is a pure function on one `color_t` (bytes
r, g, b, a). Stock uses `#FF1448`, `#7F0A24`, the pressed tint `#3D1920` and `#FF144840`, all
stock red blended with a neutral: each channel is `t * red + k`. Least squares against red with
the mean removed gives `t` (in 1/4096), then `k`. A color within `RED_TOLERANCE` (8) of that
blend, with `t` between 1/16 and 17/16 and `k` not below the tolerance, becomes `t * tone + k`
for one of the preset's tones (`ACCENTS`): the red tone for text colors (a property name ending
`text_color`, `tk_str_end_with`) and image pixels, the light tone for every other color property
and gradient stop; alpha is kept, and anything else, greys and other hues included,
is returned as it was. Anti-aliased edges onto black, white or a transparent background are such
blends, so they follow. No preset's colors are red blends, so mapping twice changes nothing.
Crimson returns every color unchanged, so its theme is stock.

- `style_get_color(color_t *ret, style, name, default)` returns its color through the hidden
  first argument. The hook runs stock through a trampoline and maps `*ret`, comparing the
  property name only when the color maps. Stock first asks `style_get_gradient` for every color
  (`bal` at `0x649fe8`; `style_data_get_gradient` turns a plain color into a one-stop gradient),
  so the gradient hook leaves the call that returns to `0x649ff0` unmapped, and the color hook
  alone picks the tone. The builder pins that `bal`.
- `style_get_gradient(style, name, gradient_t *out)` (`0x649f3c`) is a 12-instruction leaf with
  no GOT setup: null checks on the style and its vtable, then a tail call to the vtable's
  `get_gradient` (+0x18). The builder pins its first three words (`0x10800009, 0, 0x8c820000`)
  and replaces the first two with the jump; the payload repeats the checks, calls `get_gradient`
  through `$t9`, and maps the stops only when it filled the caller's `out`: `gradient_t` is 0x4c
  bytes (`gradient_init`), with the stop count at +8 and up to 8 `{color, offset}` stops from
  +0xc (`gradient_add_stop`, `gradient_get_first_color`). Widget backgrounds come this way.
- `image_manager_add(manager, name, bitmap_t *)` copies a freshly decoded bitmap into the cache.
  The hook maps its pixels first, only for plain theme image names (no `/` or `:`, so covers by
  path, `file://` or online URL are never touched), and only when the format
  is one of the 32-bit ones: `bitmap_t` has w at 0, h at 4, the format as a u16 at 0xe
  (1 RGBA, 2 ABGR, 3 BGRA, 4 ARGB in memory order, 4 bytes each by `bitmap_get_bpp_of_format`),
  its row stride from `bitmap_get_line_length`, and the pixels from
  `bitmap_lock_buffer_for_write`/`bitmap_unlock_buffer`. Premultiplied pixels are red blended
  with black, so they map the same way.

The confirm pop-up's discs (`confirm_ok`, `confirm_cancel` and their pressed images, names
starting `CONFIRM_IMAGE`) go through the same mapping with `CONFIRM_SURFACE` (`#2B2B2B`) as the
tone under every preset, Crimson included ([ipod.md](ipod.md#pop-ups)). The quick settings'
control discs (names starting `DROPDOWN_IMAGE`, `drop_`, except the brightness suns, `DROPDOWN_SUN`)
take the preset's red tone; when that tone is brighter than `GLYPH_LIGHT_MAX` (Graphite's silver),
an image that holds red also maps its neutral glyph pixels to `CONFIRM_SURFACE`, so the white glyph
turns dark ([quick settings](ipod.md#quick-settings)). Grey discs hold no red and are unchanged.
Any other image that holds red and an opaque pure-white pixel (a switch's knob, a disc's glyph; `#7F7F7F`
on a pressed disc) takes
the light tone instead of the red one, as do button backgrounds (names starting `BUTTON_IMAGE`,
`btn_`), whose white label is a widget's text; an image with red alone (a tick, the time page's
colon) keeps the red tone. Only Graphite's two tones differ, so only it scans for white.
The settings rows' category icons (`settings_icons` in `patch/ipod.json`, which the builder
writes to `SETTINGS_ICON_NAMES` in `stock.h`) are never mapped: several use stock red as their
category colour (Network, DLNA, Wi-Fi, Backlight), like the purple and orange ones.
`red_map` is the mapping with an explicit tone;
`accent_map` is it with the preset's tone, and the identity for Crimson.

Changing the accent saves it, sets the progress fill, calls `image_manager_unload_all(image_manager())`
(`0x645024`) and `widget_invalidate_force` on the window manager. Widgets ask for their style
colors, gradients and images on every paint, so the next frame decodes the images again through
the hook and shows every recoloured part; nothing needs a restart.

## Page transitions (iPod)

Stock V1.32 carries AWTK's window animators and uses one: `saverscreen_page.bin` has `close_anim_hint` `slide_left(duration=200,easing=cubic_out)`, the only hint in the stock assets. The window manager builds the animator named by a window's `anim_hint` (`window_animator_htranslate_create`, `0x683a08`, for `htranslate`) when it opens or closes. `navigator_to_with_context` (`0x4ec758`) opens a page above the rest and `navigator_back` (`0x4ec8e0`) is `window_manager_back`, so the page below stays alive and Return reverses the slide.

iPod sets the hint in its assets ([ipod.md](ipod.md#transitions)). `htranslate` animates two snapshots. `window_animator_prepare` (`0x682ee8`) paints both pages into offline canvases, through the payload's paint hooks, before `window_manager_is_animating` (`0x66daf4`) becomes true and while the sliding page is the top window; a hinted page is not painted before that, so its snapshot is its first paint. Each frame then blits the snapshots and paints only the status bar. The payload follows the snapshots in four places (`slides()`, `patch/navigation.c`). A surface whose own window is under a sliding top window draws the row it holds and nothing else: loading, recall and settling read the top page's state. A sliding page reveals its remembered row at once instead of by the glide, so it does not arrive mid-glide. Home's art is checked when Home itself is painted, not only when it is the top window. After a touch, a Return by button ends [touch mode](#touch-mode) on a 0 ms timer instead of at once: the closing page's snapshot, painted inside stock's handling of the release, keeps its row hidden, while the page behind shows its own.

## Status bar (iPod)

The background hook also handles top-level widgets, whose parent is the window manager. The status bar widget, which `system_bar_init` stores in the `system_bar` global (`0xa3a6d0`, a size-checked `CONTEXT_DATA` entry), gets one `canvas_fill_rect` in a darker color, `BAR_COLOR` (`#242424`), without a highlight, with the LCD fill color restored.

Painting the bar or the top window also updates `label_clock` in the bar with the device's local time: `time` and `localtime` (the stock libc imports, through the payload's GOT trampolines) give the hour and minute (`struct tm` `+8`, `+4`), written through `tk_snprintf` as `%d:%02d %s`, a 12-hour clock without seconds or a leading zero (`12:05 AM`, `6:14 PM`), then `widget_set_text_utf8`. A failed `time` (`-1`) or `localtime` (null), or an out-of-range field, shows `--:--`. The minute of the day (plus one, `~0` for `--:--`) is kept in the scratch page, so the label is looked up and written only when the minute shown changes; the bar repaints at least once a second through `systembar_showface`, so the clock turns over within a second, including after the screen wakes. Every page and dialog shows it. There is no volume flash: stock `on_wm_keyup_fun` opens `dialog/volume_dialog` on every volume turn (`0x4e8bb0`).

The same paints run `bar_sync`. `systembar_showface` (`0x52f610`) sets `img_bt`'s image every tick: a codec badge (`bar_sbc`, `bar_aac`, `bar_aptx`, `bar_aptxhd`, `bar_ldac`, by `bt_showcoding`) while Bluetooth is linked, otherwise `bar_bt` or `bar_btcon`. It also sets `img_battery`'s image (`bar_charge`, `bar_lowcharge` under 15%, else `bar_battery`), `label_battery`'s `%d%%` text and `progress_battery`'s value, and never the battery widgets' visibility. A badge that differs from the last one arms a `CODEC_MS` UI timer, whose steps set `widget_set_opacity` (`0x659f24`, the widget's `+0x34` byte, which `widget_paint` applies as the canvas global alpha) down and back up, switching the image to `bar_btcon` halfway. After that the bar's background paint, which runs before its children, puts `bar_btcon` back over each badge stock sets again, so no badge frame is drawn. A hidden `img_bt` or a non-badge image other than `bar_btcon` ends the flash. `bar_sync` then hides `img_battery` and `label_battery` and shows `view_battery` with `widget_set_visible`, which returns early for an unchanged state and otherwise marks the parent for relayout (`widget_set_need_relayout_children`). The slot is sized to its ink: a percentage is its digit count times the `'0'` advance plus the `'%'` advance, both measured with `canvas_measure_text` on the first battery paint (`BATT_PCT_W` until then). `view_battery` is painted in the background hook from the level (`label_battery`'s text, since stock sets `progress_battery` to 0 while charging) and the charge state (`img_battery`'s image), and is invalidated when those or its displayed mode change. `BATTERY=3` uses a compact 32×16 solid rounded battery with dark 12 px digits inside, omitting the percent sign; its body follows the charge-state colour. Resizing the slot immediately relayouts its parent row.

## Now Playing (iPod)

`playing_page_init` (`0x52ca88`, standard PIC prologue, resumed at `0x52ca94`) registers the page's handlers, runs the page update (`0x52b6f4`) once and starts a 250 ms widget timer (`playing_timer_start`, `0x52c114`) that runs it again. The update finds each widget with a recursive `widget_lookup`, skips any it does not find, and gets the times from `player_playtime_and_length` (`0x514128`): elapsed and total seconds from `mclGetPlayTime` (`0x5ac078`), less a CUE track's start, elapsed clamped to the total, both 0 while stopped. It sets `slider_play` to value = elapsed, max = total, and formats both labels with `toolsTimeItoa` (`0x5bc410`): `%02d:%02d`, or `%02d:%02d:%02d` from an hour. `label_playlen` is its only reference to that name.

The hook runs the stock init, then caches `label_ipod_pos`, `label_ipod_album`, `label_ipod_remain` and the slider, and syncs them. It also caches `img_cover`, whose border paint (after the image) rounds its corners: for each of the `NP_ART_RADIUS` rows of a corner, one `canvas_fill_rect` outside the arc and one edge pixel at the alpha it leaves uncovered, in 1/16 pixel from an integer square root, both in the page's black. Painting the top window or the status bar syncs them again, as for the clock. The position is `MCL_POS + 1` of `deque_size(*mcl_pdeqplaylist)` ("3 of 12"), empty without a current record. The album is that record's `REC_ALBUM` (the record comes from `queue_now`, which Home's art shares), or, once `player_get_id3info` (`0x5146bc`) has parsed that record's file, the album it parsed: `g_play_id3_info` (`0xa4103c`, `0xa9c` bytes) holds the parsed path at `+0`, album at `+0x404`, artist at `+0x504` and title at `+0x684` (`now_tag`). When a folder play (class 1) reaches its last track with the folder-jump setting on (Folder Skip, the byte `0xa3be53`), `mclNextSong` calls `on_player_autochange` (`0x513fc0`), whose `toolsLoadNextDir` and `player_refresh_playqueue(1)` replace the queue with the next folder's untagged file records, and only the parsed tags name the next album. Every stock folder jump tests class 1, so Coverflow plays its albums as stock's album class `0xff10` and Most Played and Shuffle Songs as `0xf001`. `album_memory` also writes the album into `g_memory_info` (`+0x60d` Unknown flag, `+0x611` name), as `player_load_songlist` does for stock lists, so stock resume rebuilds that album with `getMusicByAlbum`. Home's art keys its Coverflow cache lookup the same way. The remaining time is the slider's max less its value, in stock's format with a leading minus, so it matches the elapsed label and follows a touch drag. Each label is written only when its source changes (position, queue length, album string pointer, or those seconds); `EVT_DESTROY` drops the cache. Stock's total label stays hidden.

The V8.6 folder-rollover regression in `test/patch.py` executes stock `player_mainscheduling` → `mclAutoChange` → `mclNextSong` → `on_player_autochange` → `toolsLoadNextDir` → `player_refresh_playqueue` → `mclLoadPlayList`, then stock tag parsing, cover-worker completion and the Now Playing timer (`0x52bffc`). Filesystem enumeration, tag decoding, image decoding and the audio decoder are mocked at their boundaries; the harness does not supply the resulting player metadata globals. Equal-sized and one-track sibling folders, reused positions, missing tags/art, consecutive transitions, and delayed scheduler/cover completion pass in Stock and iPod. iPod's paint hooks also verify album text and Home art before and after completion. This does not reproduce a V8.6 regression, so no additional metadata firmware change is made.

**Info page** (both builds). The page update fills the info page through `0x52a508` (its one call, a `bal` at `0x52baf4`, after the player status checks): `label_album`, `label_genre`, `label_encode`, `label_year`, `label_bits`, `label_kbps` and `label_sample` as `%s:%s` or `%s:%d…` (`Album:Kid A`, `Bit Depth:16bit`, `Sample Rate:44.1kHz`; `%s:%s` is also wpa_supplicant's literal, so stays), `label_size` as `%s:%.2fMB`, and `label_location` as the bare folder with `/mnt/mmc/` as `SD:/` (it looks up `player_location` and never uses it), a missing value as the first `player_unknown`, which en_US has twice ("Unknown Artist", then "Unknown"). Its labels **Genre** and **Year** are `LABELS` renames of `genre` (which the search page's tab shares) and `player_era`.

`set_repeatpoint`'s marker placement (`0x52a268`) puts the 3x10 A-B markers at x = 50 + t \* 290 / length, y 250. iPod's bar is 8 pixels at y 251, so it keeps y and patches the two immediates in `ipod.json` to its x and width. Its dragger is skipped when the `icon` style lookup is empty and `border_color` is transparent, and the fill then ends exactly at the value; the slider's style name has no theme entry, so no theme icon applies. `slide_with_bar` still seeks on a tap or drag anywhere on the bar.

## Visualizer (iPod)

hciplayer's PEQ filter (`patch/peq_player.c`) taps what it plays, after `peq_process`, into `/tmp/q2vis` (tmpfs), a `vis_tap` (`patch/peq.h`): a ring of `VIS_RING` stereo float frames, the frames written (`seq`), the ring's rate and the `CLOCK_MONOTONIC` time of the last write. It keeps the first two channels, and above 48 kHz every `rate / 44100`th frame, so the ring holds about 1.5 s at any rate, room for hciplayer's 500 ms ALSA buffer (ao_alsa's `buffer_time` 500000 at `0x438a2c`, 16 periods). No lock: the writer stores the frames, then the rate and stamp, then `seq`, and the reader tolerates a torn frame. demo makes the file (`open`, `ftruncate`) under `/tmp/q2vis.tmp` and renames it, so hciplayer never maps a short file; hciplayer looks for it (`open`, `mmap64`) once a second of audio (frames counted, no clock call) until it appears. demo maps it read-write and bumps `want` each tick; after a second of audio with no bump the writer stops copying, and the next bump clears the ring, so a return never shows audio from before.

`ringnav_playing` adds the page (`visualizer_attach`, `patch/visualizer.c`): a `s_listitem_black` `list_item` appended to `slide_view` at run time, so a tap clicks it but a swipe still slides, and the page dots get `max` set to the new child count. The page only takes taps: the `slide_view` clips a page added at run time to a sliver when it paints it, so the visualizer draws in the paint hook of Now Playing's window instead, after all its children, clipped to the slide area and with the canvas origin moved there, and its Halo art is an `image` child of the window over the area's centre. That image takes `img_cover`'s image name and draw type, so stock's reload of the cover (load, set, unload) refreshes it too, and shows only while the Halo draws. Painting starts a `1000 / VIS_FPS` ms timer, which removes itself once Now Playing is not on top, the `slide_view`'s `value` is not the last page or the screen is off; each tick invalidates the slide_view. Nothing draws unless settled: no window animation, and the page's own paint, which runs just before the window's in the same frame and draws nothing, last found its canvas at the slide area's left edge (and hides the Halo art the moment it does not), so the page is not being dragged or sliding (`value` only changes once a slide ends); a tap leaves it there, and the timer skips repaints while a finger is down. 1.5 s after the audio stops (everything at rest, the style name faded) it repaints once more, with the track's title and artist (`scrlabel_title`, `scrlabel_artist`, joined by a middle dot) where the style name shows, then stops repainting. A window paint that finds the page on top of the slide_view but not settled (under a closing window such as the lock screen, mid-slide or dragged) arms a `VIS_RETRY_MS` (250 ms) one-shot that invalidates the slide_view once it is settled; paused, nothing else would draw it. Each tick takes `VIS_N` (1024) frames ending `VIS_LATENCY_MS` (480) behind the last write, moved on by the time since it: that buffer, which MPlayer refills a period at a time, less about a period. Bluetooth adds its own delay, so it stays the sync knob. It runs a Hann window and a radix-2 FFT over the mono mix and takes each of 64 log-spaced bands' (40 Hz to 16 kHz) loudest bin, 0 at `VIS_FLOOR_DB` below a full-scale sine and 1 at it (`vis_bands`). Bars rise fast and fall at `VIS_DECAY`, and caps hold `VIS_HOLD_MS`, then fall at `VIS_GRAVITY`. The VU needle is a one-pole follower of the window's RMS (tau 65 ms, 99% in 300 ms) on the meter's voltage scale, with 0 VU at `VIS_VU_REF_DB` dBFS; the LED lights at `VIS_LED_DB` dBFS peak. With nothing playing (`mclGetPlayStatus` not 2, or no write in a second) everything comes to rest. Drawing uses the stock vgcanvas entry points (`canvas_get_vgcanvas`, which clips to the canvas, then its path, fill and stroke calls; `float_t` is a float and `color_t` passes by value), translated to the slide area.

The tap sees only what the filter sees. Boot instantiates the filter only when an EQ was left on (`PLAYSET/EQFLAG`, see [Parametric EQ](#parametric-eq)). So with the EQ off the page's first timer tick (outside the paint) calls `peq_attach` (`patch/peq_ui.c`): what the editors' Off does, `peq_stock_eq`, which instantiates the filter in bypass, after making sure the [EQ state](#3eq) is saved Off, so a mode saved on while the stock flag is clear stays silent. Bypass is bit-exact, so 16- and 24-bit streams reach the output unchanged through the float conversion. DSD passes through the filter untouched, so during DSD the page rests. Boot itself is left alone: a listener who never opens the page keeps the stock chain.

## Boot resume (iPod)

Stock `home_page_init` resumes when Memory Playback (`g_memory_play`) or car mode (`g_carmode`) is set. `memeory_startplayer` (`0x5164e0`) reads the saved state, rebuilds the queue into a new deque, sets the saved position with `mclSetStartSeekTime` when `g_memory_play` is 2 or in car mode, and returns the track index; it neither plays nor opens a page. Home then calls `navigator_to_with_context("playing_page", ctx)` (the `jalr` at `0x523de0`) with `ctx` `{queue, index, class, mode}`, mode 2 in car mode and 3 otherwise. `playing_page_init` passes `ctx` to `player_start` unless the class is `0xff`; `player_start` loads the queue, starts the player and pauses it (`mclSetPause`) unless the mode is 2.

iPod makes that `jalr` a checked `jal ringnav_boot`; the delay slot still stores the mode. In car mode `ringnav_boot` makes the stock call unchanged. Otherwise it makes the page's `player_start` call without the page, so the queue and track come back paused and Home stays; the saved time is restored in Location mode, while Track starts at the beginning. Home destroys its deque afterwards, as before, since `mclLoadPlayList` copies it. The page's two resets before `player_start` (key-seek mode and a countdown) are page state, set again when it opens. `hciplayer` touches `/tmp/notfile` or `/tmp/notsupport` for a missing or unsupported track; the window manager's `on_wm_timer_dialog` (`0x4ea784`) turns them into a `msginfo_dialog` toast on any page, and `playing_page_init` only deletes stale ones, so a bad restored track still shows its toast on Home.

The English stock labels are Memory Playback: Off / Track / Location and
System: In-Vehicle Mode. Home's Now Playing action (`on_home_playing_onclick`
at `0x5237d0`) calls `on_backplay_click` (`0x4e805c`), which opens the player with
class `0xff`; this skips `player_start` and preserves the paused state. Play/Pause
resumes audio.

## Scrub (iPod)

**Stock audit.** `playing_page` is not a navigation context, so a centre release (218, the power key) passed through to `on_wm_keyup_fun`, whose `screen_action` (`0x4f77d4`) turns the screen off, and a wheel release to the same handler, which changes the volume and opens `dialog/volume_dialog`. The page's own key-up handler (`0x52c248`) only knows Return and keys 222/223. Those drive stock's key seek: a long press sets `0xa3a6c0` (`0x529df0`), key-down (`0x52c754`) calls `playing_timer_clear` (`0x52c634`), sets the mode byte `0xa3a6c1` to 1, steps `slider_play` 5 seconds within `[0, max]` and writes `label_playtime`, and key-up calls `player_seek_time` (`0x51454c`) with the slider value, then `playing_timer_start` (`0x52c114`). A touch drag takes the slider's handlers from the page's `widget_foreach` visitor (`0x52ae6c`): value-changing (`0xf`, `0x52c950`) writes the label and, in mode 0, clears the timer and sets mode 2; value-changed (`0xe`, `0x52c5fc`) seeks the same way only in mode 2 (`0x52c364`). `player_seek_time` takes track seconds: it adds the current record's CUE start (`+0x48`), pauses DLNA, calls `mclSetSeek` (`0x5ab1ac`), then polls `player_playtime` every 10 ms, up to 2 s, until it reaches the target. `player_seek_start` (`0x5143a8`) is DLNA's and not used. `slider_set_value` emits will-change (`0xd`) and changed (`0xe`), never changing, so a set value in mode 0 neither seeks nor writes the label.

**Scrub.** On the top `playing_page`, with no window animation or pressed pointer, the key-up hook takes the centre button. A release arms a `DOUBLE_CLICK_MS` timer, and a second release before it ends cancels it and starts scrub. While scrubbing, `center_press` arms no timer: a release ends the scrub at once, and a release within `DOUBLE_CLICK_MS` after that one is swallowed, so neither a single nor a double press turns the screen off. Otherwise the timer, a single press, replays the centre release to stock `on_wm_keyup_fun` (`0x4e8934`, which reads only the event's key there), so the screen turns off as on any other page; a release after an overdue timer runs it first and then passes through to stock. Starting calls `playing_timer_clear`, reads the slider value as the target and sets the slider's `style:normal:fg_color` to white. While scrubbing, a wheel release moves the target by `SCRUB_STEP` (5) seconds times the 100 ms ramp's step (`ramp` keyed on the slider with `WHEEL_RAMP_MS`, so 5 to 40 seconds; the lists' gentler curve does not apply: every tick moves the target), clamped to `[0, max]`. It sets the slider value, writes `label_playtime` in stock's format and syncs the remaining label, marks the target moved if the step changed it (a tick against an end does not), rearms the `SCRUB_MS` (3 s) end and swallows the release; nothing seeks while ticks come in, however far apart. Ending seeks once, with `player_seek_time(target)`, the stock key path's commit, so CUE tracks stay track-relative, and only if the target moved; it then restores the accent's light-tone fill. Paused (`mclGetPlayStatus` 3), `player_seek_time` would resume the track (`config_outputchannel`, then `mclSetResume`) to reach the target, so the scrub sends the seek alone, `mclSetSeek(target + the record's CUE start)`, as `player_seek_time` adds it: hciplayer's `mcl-seek` handler (`0x42c5b4`) mutes the DAC and flags the seek, and its seek (`0x42b010`) leaves the DAC muted while paused, so the track stays paused and plays from the target at Play. Unlike `player_seek_time`, it does not pause DLNA first, so a paused seek is not reported to a DLNA controller. After a seek, `playing_timer_start` waits for `settle_poll` (every `SETTLE_MS`, 250 ms): paused, the player's second stands still until Play, and the page's timer would put the bar back on the old second. The bar keeps the target until `player_playtime_and_length` is within a second of it, the track changes, the player stops, or `SETTLE_PLAY_MS` (2 s) of playing pass without it; a new scrub, the lyrics' wheel or an exit drops the wait (an exit that ends a scrub keeps the one its seek starts). A paused seek is remembered with the player's second when it was sent: reopening Now Playing on the same track, still paused and at that second, puts the bar back on the target and waits again, so a new scrub starts from it; playing or another track forgets it. Without a seek the timer restarts at once. It ends on a centre press, the timeout, Return (swallowed on the page), a touch (before the slider sees it, so a drag seeks the stock way), another top window, or the page's `EVT_DESTROY`, which drops the target. After the playing track changed (queue position and path, recorded at the start) the target is dropped: the next tick ends the scrub without moving it, and any other end does not seek. `player_seek_time` can block the UI thread briefly, as stock's key seek does; it now runs once per scrub instead of after every pause of 150 ms between ticks. The mode byte stays 0 throughout. Outside scrub the wheel stays on the volume.

**Lyrics.** The page's 250 ms timer also keeps the lyrics in view: when `mclGetLyricSize()` is positive it finds the current line among `scroll_lrc`'s children (`0x52bcc8`), sums 25 px per wrapped 225 px row up to three lines before it, and calls `scroll_view_scroll_to(scroll_lrc, 0, y, 10)` whenever the view's y offset (`+0x84`, `SCROLL_Y`) differs, so a moved offset lasts one tick. `ringnav_playing` keeps `slide_view` and `scroll_lrc`. On the top `playing_page`, a wheel release while `slide_view`'s value is 1 (the lyrics page), `scroll_lrc` has children and `mclGetLyricSize()` is positive goes to `np_lyrics` before scrub: it ends any scrub (`scrub_end`, committing a moved target), calls `playing_timer_clear` on the first tick, sets the offset `LYRIC_STEP` (25) px up or down within `[0, content height - view height]` with `scroll_view_set_offset`, rearms a `SCRUB_MS` timer and swallows the release. The timer, a scrub start, and every scrub exit (`np_cancel`: a touch, another top window, the page's `EVT_DESTROY`, which leaves the stock timer off) end it; the timer and `np_cancel` call `playing_timer_start`, whose first tick scrolls back to the current line. Any other page, or no lyrics, leaves the wheel on the volume.

## Pull-to-search

Pull-to-search starts from the existing touch hook only on a real pointer-down (`0x100`; the stock window manager registers `on_wm_tsdown_before_fun` for that type), while the separate move-before callback (`0x102`) tail-calls the same entry point. It applies to Local Songs (`localmusic_page`) in iPod only, and to Internet Radio (`radio_page`) in both: Folder view has no working stock search, so it is excluded. It checks the screen coordinates, list bounds and initial scroll offset, then uses page-owned move/up-before-children callbacks (`0x102` / `0x104`). A downward drag of at least `PULL_CLAIM_PX` (8), greater than its horizontal travel, claims the pointer. The native abort event (`0x107`) clears pressed descendants; a widget-owned suppression flag also rejects late row clicks until the next touch. A floating, non-interactive label overlays the page without changing the list or its indices. Release at `PULL_SEARCH_PX` (48) invokes the stock Local Songs search callback `0x5241c4`, which opens `dialog/search_dialog` without replacing the browsing page; on Internet Radio it calls `radio_search` (radio.c) instead. Moving back below the threshold cancels activation. Page/surface destruction, backgrounding, close and input interruption clear the gesture. The stock quick-settings start region (`y < 31`) is excluded.

`patch/ipod.json` records the added private prologue and native event ABI instructions alongside the compact sites and assets. The builder checks them against the pinned stock executable and checks the byte sizes of all referenced global flags/values.

## Manual skip

Manual Next and Previous run `player_change_music` (`0x51503c`), not `mclNextSong`. At queue index `n-1` (or `0` for Previous) it loads the next (previous) folder itself (class 1 with Folder Skip on), or in List Play wraps to the other end with `mclSetPlayPos`. In List Play, `ringnav_next` and `ringnav_change` stop a library queue (`0xfxxx`) at its last track instead (`list_end`), so the end of an album stops on a manual Next as it does at a natural end; `ringnav_change` returns 0, since its caller toasts -1 (no storage) and -5. In Repeat All with Folder Skip off, every branch calls `mclNextSong(0)`/`mclPrevSong`. While advanced playback is active, `ringnav_change` runs stock with `MCL_MODE` 3 and Folder Skip 0, then restores both, so the hooked `ringnav_next`/`ringnav_prev` choose the track and stock's refresh tail (tags, notifications, Bluetooth headset info) still runs. It writes `MCL_MODE` directly, since `mclSetPlayMode` would end advanced playback. `ringnav_mode` (the hook on `mclSetPlayMode`) ends advanced play through `playback_clear` for a user's stock mode choice, except stock Shuffle (2) while Shuffle Albums/Folders is on, which keeps the groups. `ringnav_prev` clears the `seen` flag of the track it leaves, so the next Next returns to it instead of skipping it. Shuffles draw from `rand_below` (`playback.c`), an xorshift32 seeded once from `toolsRandnum` and `time_now_ms`, because stock's generator alone repeated itself between shuffles started close together (the hold menu lists Next/Previous Album, first, only while `playback_option(0) >= 3`). `player_initconfig` (`0x513374`) also calls it, re-applying the saved mode whenever hciplayer connects (`player_reconfig`, set by `mclParseCommand` on accepting its socket), after a boot resume too; that is no mode choice, so `ringnav_mode` passes it straight to stock, told apart by its return address (`INITCONFIG_MODE_RET`, checked by the build). Earlier at boot, `config_init` calls `config_playmode` (`0x4f999c`) before Home restores the queue. That call goes through `ringnav_bootmode`, which marks it as restoration so `ringnav_mode` applies the setting without deleting the snapshot; explicit mode choices still clear advanced playback.

Memory Playback's `ringnav_memory` restores the saved snapshot using `getAllMusic(3)`, which avoids the pinyin title sort. A temporary index (8 bytes per library row) is sorted by file path and CUE start/end, then binary-searched for each saved occurrence. Equal identities retain the query's first row. The snapshot still controls queue order, history and playback position; missing files are skipped and unindexed files retain the stock directory fallback. Index allocation failure frees the temporary state and falls back to stock resume without rewriting the snapshot. `test/playback.py` checks those cases and bounds path comparisons for a 256-track restore so a full-library search per track cannot return unnoticed.

## Bluetooth LDAC quality

The Quality page's rows are LDAC HQ, LDAC Standard, LDAC Connection (auto), aptX HD, aptX, AAC, SBC HQ and SBC (`g_btcoding`, `[SYSSET] BTCODING`). `switchBtPriority` (`0x4f0314`) sends `btctl_set_ldac_quality` over D-Bus to `bluealsa` (`SetLDACQuality`). bluealsa maps 0x15, 0x16 and 0x17 to the encoder's eqmid HQ, SQ and MQ, and maps any other value to adaptive bit rate. Stock sends 0x16 (SQ, 660 kbps, or 606 at 44.1 kHz) for both HQ and Standard. `LDAC_HQ` rewrites the jump-table dispatch to keep `0x15 + row` in the frame's free `0x14($sp)` slot and loads it in place of the constant. HQ then sends 0x15 (990 / 909 kbps), Standard 0x16, and auto still 0x18. Turning Bluetooth on applies the saved row again, and Rockbox plays through the same daemon.

Auto already uses Sony's native ABR controller, including the intermediate 492 and 396 kbps rates (48/96 kHz), alongside 990, 660 and 330. These are discrete encoder frame sizes, not arbitrary 1 kbps increments. The shipped `libldacBT.so.2.0.19` supports them through `ldacBT_alter_eqmid_priority`; `libldacBT_ABR.so.2.0.0` selects them from queue congestion and raises quality after recovery. Bluealsa's `0x416388` maps Auto to an initial SQ encoder with ABR enabled; its encode loop calls `ldac_ABR_Proc` at `0x41ab00` with the queued packet count, using a 40 ms interval and thresholds 12/8/4. The HQ fix changes the fixed HQ row only; Auto could already recover to HQ. `test/ldac.py` executes the shipped encoder's five rates, the daemon's mode mapping and the ABR controller's congestion/recovery paths. No custom rate controller is added. This does not establish a cause or fix for sustained distortion requiring reconnect, or USB-dongle heat; those need device reproduction.

## Bluetooth AAC

When a headset opens the A2DP stream itself (AirPods taken out of the case), it picks AAC at 44.1 kHz. Stock `bluealsa` is still fed 48 kHz audio and drops about 8% of the AAC frames, so the audio is choppy until Bluetooth is toggled; a connection the Q2 opens picks 48 kHz. The build clears the 44.1 kHz bit in `bluealsa`'s AAC source capability, `c0 01 84 84 e2 00` at file offset `0x317b7` (object type, sampling frequencies, channels, VBR and bitrate). Octet 1 holds 8 to 44.1 kHz with 44.1 kHz in bit 0, so `0x317b8` goes from `01` to `00` and headsets pick 48 kHz, which every AAC sink must support. `ZIP_SHA` pins the stock binary, and `test/build.py` audits the allowed byte changes and checks the manifest's `bluealsa_sha256`.

Manual skips also call ALSA DROP. Stock acknowledges it after sending signal 6, but the encoder flushes PCM later (`0x4147ac`), potentially discarding the next track’s first samples. The patched DROP (`0x40cb50`) flushes the nonblocking FIFO under the PCM fd mutex before sending that signal and acknowledging the request. The encoder’s shared DROP handler discards each audited caller’s partial PCM input, restores full input capacity, and resets its pacing clock through the existing OPEN/RESUME path instead of flushing again. Natural gapless transitions do not issue DROP. `test/bluealsa.py` executes both MIPS paths with a delayed signal and empty, normal and oversized old queues; stock loses new audio and the patched binary preserves it.

## Clock

The timezone picker keeps stock's saved indices and appends the missing offsets, including Asia/Colombo (+05:30), Asia/Kathmandu (+05:45), Australia/Eucla (+08:45) and Pacific/Chatham (+12:45). `tools/build.py` compacts the existing label table into 32-byte slots and extends the row counts and boot validation; `ringnav_timezone` delegates existing indices to stock and applies the additions through `toolsSetTimeZone`, using the rootfs's IANA timezone data.

Stock loses the time zone across a power-off. Setting the time, by hand or from the network (`toolsSetRtcTime`, `0x5bc760`), runs `date -s` and then `hwclock -w`. BusyBox 1.31.1's `hwclock` writes local time unless `/var/lib/hwclock/adjtime` says `UTC`, and the rootfs has no such file, so the RTC gets the wall time of the `TZ` the player exported (`toolsSetTimeZone`). At boot the kernel (`hctosys`) reads the RTC as UTC and the player adds the time zone again, so the clock comes back off by the zone's UTC offset until the next network sync. The build changes the literal at `0x777928`, `hwclock -w` and two NULs, to `hwclock -wu`, so the RTC holds UTC as the kernel expects. An RTC last written by stock still holds local time, so the time has to be set once after updating.

## Parametric EQ

**Stock presets.** Stock's preset slots are `reset_user_eq`'s (`0x4f91a4`) constant 12 × 10 float table, modes 1-3 the zeroed custom slots and 4-11 Pop, Rock, Dance, Blues, Metal, Vocal (the `eq_scene` image), Classical and Jazz in its `eq_*` image order, in dB over the same ten bands (`set_equalizer_value` stores them plus 6). `patch/peq_ui.c` keeps modes 4-11 as `stock_gains`; picking one loads `peq_default` with those gains, bands with a gain on, and Auto preamp into the editor as a saved preset does. Nothing is written until Apply.

The PEQ adds two demo hooks: `playset_equalizer_page_init` (`0x4b642c`) builds the editor from `patch/peq_ui.c` (ten band rows, plus a spare past the last used band, up to 30), and `set_equalizer_value` (`0x4f9230`) keeps the stock equalizer filter instantiated, then sets `g_equalizer_flag` to the PEQ on/off state so the status-bar EQ icon (`systembar_showface`) follows it. The editor's ON/OFF writes the stock switch's `write_int_config(flag, "PLAYSET", "EQFLAG")`, which boot reads before instantiating the filter, so the state survives a restart. Frequency and Q open a value menu whose first row is an AWTK `edit` created at run time, keyed and styled as the stock playlist dialogs' (`kb_default_t9`, `ufloat`, `#2B2B2B` rounded), but with action text `done`: stock `edit_on_event` acts on the keyboard's OK (`EVT_IM_ACTION`) only for `done` (close the keyboard, then `EVT_VALUE_CHANGED`) or `next`, and the dialogs' `OK` relies on their own handlers, so with `OK` the value only reported on blur; its `EVT_VALUE_CHANGED` applies the text through the preset parser's number reader, clamped like Raise/Lower, and its `EVT_FOCUS` (`0x10e`) starts a 16 ms timer that finds the keyboard window under `window_manager()` and switches its `panel` pages to `symnum`, the number keys, trying up to 20 times since the keyboard can open a moment after the focus. Auto preamp is minus the peak of the combined response of the louder channel (1024 log-spaced points per channel, 20 Hz-20 kHz at 48 kHz). A band edit, including a gain picked from the wheel list, recomputes it only when the preamp was within 0.05 dB of Auto before the edit, so a picked or imported preamp stays put; nothing extra is stored. The editor handles Return (key 170) itself, since it replaces the page init that registered `on_common_keyup`. On the main and band screens a `PEQ_GRAPH_H` view under the title shows the draft's response (`response`, the same `|H|^2` as Auto preamp, one point per column, 20 Hz-20 kHz, ±`PEQ_GRAPH_DB`), drawn by `peq_paint` from the paint hook: a grey grid with 100, 1k and 10k labels, a 2-pixel vgcanvas line in the accent's light tone (white in Stock) with a fill that fades toward 0 dB, the other channel's line dimmer when left and right differ, a ring per band in use, the edited band's larger and filled; grey with no fill when PEQ is off. Rows show the caption on the left and the value right-aligned in grey; off bands and display-only rows are grey. The **Presets** row's value names the preset loaded from there, and keeps the applied one's name until the active preset changes. In `/usr/bin/hciplayer` (modified MPlayer 1.3.0, pinned by `PLAYER_SHA` in `tools/peq.py`) the equalizer descriptor's open pointer at `0x893e0c` is redirected to `patch/peq_player.c`, loaded through the player's unused `PT_NULL` header at `0xe10000`. Stock skips the equalizer above 48 kHz (`slt` against 48001) in two places: the EQ-on command (`beqz` at `0x42ced0`, to the `===setequalizer off===` log) and the per-stream insert (`bnez` at `0x42fd84`, around the add-equalizer call `0x4291ac`). The build makes the first a nop and the second unconditional (`EQ_RATE_GATES` in `tools/peq.py`, pinned), so the filter runs at every rate; `peq_compile` accepts 8-384 kHz. DSD is the exception: it reaches the chain as integer PCM, possibly DoP, whose bits must arrive unchanged, so config accepts the format as it comes and `play` leaves every block alone when the playing codec (`mpctx`, a pointer at `0xaf9e30`, `+0x2c` `sh_audio`, `+4` `codec`) has driver `dsdiff` (`+0x3e0`; the vendor's decoder for dsf, dff and SACD iso) or a name starting `ffdsd` (`+0x3d0`); so do rates outside 8-384 kHz and unknown formats. It never detaches (2): the per-stream insert (`0x4291ac`) adds it with `af_add` (`0x44d098`), which returns the new filter even when its reinit (`0x44c1c4`) detached and freed it, and the insert then sends the gain set to the freed instance. The player re-adds the filter at each file load (`0x4224cc` sets the insert state back to pending), so the next PCM track is equalized again. The player reads what plays from the [EQ state](#3eq) in `/mnt/data/peq-active` on the playback loop, never in the PCM callback; `patch/peq.c` holds the shared parser, storage and biquad DSP.

A band's `enabled` is 0 off, 1 both channels, 2 left only, 3 right only (stream channels 0 and 1); `balance` (dB) attenuates the left above 0 and the right below, so it never adds clipping. APO `Channel:` sections set the scope of the filters after them, and per-side preamps become the louder side's common preamp plus `balance`. Out-of-range OFF filters, the blank slots some exporters write as `Fc 0 Hz … Q 0`, are skipped. Presets are `Q2PEQ02`; ten-band `Q2PEQ01` files load with `balance` 0 and default bands 11-30. The DSP runs bands only up to the last one in use, or still draining memory carried from the previous preset.

## 3EQ

3EQ is the **Simple** tab of stock's **Audio settings → EQ** page, which `peq_page_init` builds with two tabs (`ui.tab`), opening on Simple every time; **Advanced** is the PEQ editor above. On Simple and on Advanced's main screen the 48 px title label is the tab bar (`ui.bar`, drawn by `tabs_paint`): the open tab white over an accent line, the other grey. A message takes the bar until the next action. A press on the bar picks a tab by its half (`tab_to`, rendered from a timer, never inside the press). Switching tabs changes nothing that plays. Simple is one view that `e3_paint` draws from `ringnav_paint`: the switch and **Reset** under the bar, then three sliders over a 0 dB line. `eq_key`, from `ringnav` after `xfade_key`, takes Simple's wheel and Centre: the wheel moves between the bar and the five controls, Centre (`center_press`, so a double press still turns the screen off) switches tab, flips the switch, resets or takes a slider, whose gain the wheel then steps by 0.5 dB until Centre or Return; the page's key-up handles Return. On Advanced's main screen the list keeps the wheel, except a turn up from its first row (or with none selected), which `eq_key` takes to put the bar in focus (`ui.tabs`, the list's `_ringnav_index` -1); a turn down returns to row 0 and Centre opens Simple. A press on Simple's view (`EVT_POINTER_DOWN`) picks a control; the page's move and up handlers (`EVT_POINTER_MOVE_BEFORE`, `EVT_POINTER_UP_BEFORE`, as pull-to-search's) drag a slider in 0.5 dB steps.

**Filters.** `eq3_bands` gives the shared engine three bands, Q 0.707: a 155 Hz low shelf, a peak at 900 Hz for a cut or 1,750 Hz for a boost (0 dB is an identity band), and a 5 kHz high shelf, each -6 to +6 dB. The filter types and rough frequencies follow [Listener's measurements of Apple's AirPods EQ](https://headphones.com/blogs/features/apples-airpods-eq-is-it-any-good); the Q, the 155 Hz within its reported range and the ±6 dB limits are Q2 Pod's own, not Apple's coefficients, and its volume-dependent limits are not copied. The preamp is PEQ's Auto (`headroom`, minus the response's peak). A change crosses over in the engine's 20 ms ramp, including Mid's frequency moving across 0 dB. A shelf above Nyquist is skipped at that rate, as any band is.

**State.** `/mnt/data/peq-active` holds one `eq_state` (`patch/peq.h`), written whole (`.tmp`, `fsync`, rename) with the magic `Q2PEQ03`: the mode (`EQ_OFF`, `EQ_3`, `EQ_PEQ`), `hold`, the last applied PEQ and the 3EQ. `eq_load` reads it, or upgrades a `Q2PEQ01`/`02` preset from before 3EQ (PEQ on unless it was bypassed, 3EQ flat); a short, long or invalid record reads as none (Off, PEQ's defaults). `eq_effective` is what plays: the mode's preset, bypassed when Off. The player reads it through `peq_load_active` on the playback loop, as before. Saved presets in `/mnt/data/peq-presets` stay `Q2PEQ02`. Every mode change goes through `eq_commit`, which saves the record, writes `PLAYSET/EQFLAG` when on/off changes and calls `peq_stock_eq`, which sets `g_equalizer_flag`, the status-bar icon, to the mode not being Off. Turning either EQ on selects it and turns the other off; PEQ's Apply keeps the mode unless PEQ is on. Slider edits are saved no more than every 250 ms (`E3_SAVE_MS`) and at once when an adjustment ends, and the player is told only while 3EQ plays, so editing an Off 3EQ changes no sound. A failed save says so in the title and keeps the gains to save again. **Hold:** turning 3EQ off on its page saves Off with `hold` set, which plays the 3EQ's preamp alone (`count` 0), so comparing against bypass is not suddenly louder; closing the page clears it.

## Large MP3s

Stock `hciplayer` reads an MP3's Xing or VBRI header for its frame count, as MPlayer does, and then, when it found one, walks every frame of the file before playing (`0x4a2d5c`, called from `demux_audio_open` at `0x491de0`): it recounts the frames for the duration, stores the first `0x5000` frame offsets (about 8 minutes) in a table at `0xd30eb0` and sets MPlayer's `hr_mp3_seek` (`0xb152b8`). That reads the whole file off the card, 140 MB for a two-hour yt-dlp mix and 700 MB for a six-hour one, so the track starts late or seems not to start, and the gapless preload of the next track does it again. A seek past the table walks frames from its last entry, as slowly. An `Info` (CBR) header skips all of it.

The build makes the branch to that walk (`bnez` at `0x48fb3c`, `VBR_SCAN` in `tools/peq.py`, pinned) a nop, so a VBR file takes the path `Info` files already take: the duration is the header's frame count, `hr_mp3_seek` stays 0 and a seek goes to `movi_start + seconds * average bytes per second` at once. On its own that seek is as exact as the bitrate is even: on the card's files the worst case was 9 s in a 2.4-hour jazz mix and 6 minutes in a 5-hour game soundtrack whose tracks differ widely.

The Xing header's 100-point table fixes that. The audio demuxer's descriptor (`0x89fd90`) has its seek slot (`0x89fdbc`, `SEEK_SLOT` in `tools/peq.py`, pinned to stock `demux_audio_seek` at `0x48d1ac`) pointed at `mp3_seek` in `patch/peq_player.c`. For an MP3 (`priv->frmt` 1, `priv` at `demuxer+0xc70`) without `hr_mp3_seek` and not a factor seek, it reads the first frame once per file with `lseek64`/`read` on the stream's fd (`stream_t +0x14`) and restores the fd's offset, since stock's `stream_seek` can reuse its buffer without seeking. `mp3_toc` then parses the Xing header: MPEG 1, 2 or 2.5 Layer III, frame count and table both present; `Info` (CBR) and VBRI keep the stock seek. The target second (`priv->next_pts`, a double at `+8`, plus the offset for a relative seek) becomes a fraction of the track and is read off the table, interpolated between its points. Stock then seeks with `SEEK_ABSOLUTE | SEEK_FACTOR` to that fraction of `movi_start..movi_end`, and `next_pts` is set to the target second, so the shown time is exact. The landing is within the table's resolution, about 1% of the bytes between two points.

## MP3 ReplayGain

Stock **Audio settings → ReplayGain** (`mcl-replaygain`) scales by the gains FFmpeg's `ff_replaygain_export` (`0x538764`) finds, which the vendor changed to store them in a global (`0xafc790`: track gain, track peak, album gain, album peak, gains in 1/100000 dB, `INT32_MIN` for none) that the replaygain filter's setup (`0x428260`) takes at the next file. lavf demuxers call it, but MPlayer probes MP3 with its own `demux_audio` first, whose `demux_audio_open` hands a leading ID3v2 tag to a vendor frame walker (`0x48e6b0`, called at `0x48f704` and `0x4923d8`). That walker stops after 2 KB of frames, reads ID3v2.4's syncsafe frame sizes as plain ones and keeps a UTF-8 frame's encoding byte at the front of the TXXX description, so `\x03REPLAYGAIN_TRACK_GAIN` matches nothing. Embedded cover art or a long comment ahead of the gains, or a UTF-8 TXXX (what most ID3v2.4 taggers write), and the track plays without its gain; only Latin-1 or UTF-16 gains near the front of the tag reach the filter.

The build points both calls (`ID3_CALLS` in `tools/peq.py`, pinned) at `id3_gain` in `patch/peq_player.c`. It runs the stock walker, then reads the whole tag again through the stream's fd, as `mp3_seek` does, restoring the fd's offset: ID3v2.3 or 2.4, an extended header skipped, frame sizes syncsafe in 2.4. Each TXXX of up to 256 bytes is decoded by `id3_txxx` (Latin-1, UTF-8, UTF-16 with either BOM, UTF-16BE) and put into an FFmpeg dictionary with stock's `av_dict_set` (`0x6ea744`), which goes to stock's `ff_replaygain_export` as the walker's does, so the gains are parsed the same way and stored only when one is there. Tags at the end of the file (APEv2, as `mp3gain` writes, or ID3v1) and the LAME header's gain are not read. `test/id3.py` runs the built player's walker, dictionary and export under Unicorn on tags of each kind.

## MQA detection

At each audio (re)init, `reinit_audio_chain` (`0x42e834`) probes an eligible stream: FFmpeg FLAC or non-AIFF PCM (codec types 13 and 11 at `sh_audio+0xd4`), stereo, 16 or 24 bit, at 44.1, 48, 88.2, 96, 176.4 or 192 kHz. The probe is skipped only when `mcl-mqadecodemode` stored 2 at `0xb10e44`; demo's sender for that command (`0x5ab554`) has no caller, so stock always probes. The probe (`0x42e5dc`) pre-decodes `0xc00` bytes (`0x20000` on output way 2), looks for the MQA sync word (`0x319207d5` in L xor R) and returns 2 for MQA, otherwise 1. Either result creates the vendor PCMDecoder (handle `0xb10d74`) and is stored as isMQA (`0xb10c54`).

Stock `fill_audio_out_buffers` (`0x42f3f4`) then passes every chunk through that decoder (`0x72f9fc`, the library's decoder and renderer) whenever isMQA > 0 (`blez` at `0x42f8c0`). It plays the library's output only when isMQA == 2 (`0x42fc48`). With 1 it plays the original `a_out_buffer`, and the converted buffer is never read. All that work does is let the library's status (`0x42f6b8`) switch a track to MQA mid-play. On the Q2, playing ordinary 16-bit 44.1 kHz FLAC, the side chain was 79% of the player thread's samples in a ptrace PC profile, and hciplayer took 12.8% of a core.

The build changes the gate to isMQA == 2 (`MQA_GATE` in `tools/peq.py`, five words), so non-MQA streams skip the side chain and what reaches ALSA is unchanged. With that, the same playback takes 2.3% of a core. MQA tracks run the decoder as before, so MQA now has to be found at the start of the track. The detector (`0x730354`) searches at most 96000 frames before it settles on not MQA, so the probe now reads that much (`MQA_PROBE`, `0x300000 >> (codec ^ 15)` bytes instead of `0xc00`): `0xc0000` for FLAC, which FFmpeg decodes to 8-byte frames at 24 bit (98304 frames, 2.2 s at 44.1 kHz), well within its `a_buffer_size` (1,732,608 bytes). PCM gets `0x30000`, as ad_pcm's `a_buffer_size` is only `0x30800` and a longer probe would fail its prebuffer and leave isMQA 0. The probed audio is played, not discarded; the probe runs once per track, not on seeks. ponytail: an MQA PCM file whose signal starts after `0x30000` bytes, or any MQA file whose signal starts after 96000 frames, plays as plain PCM; probe longer if one turns up.

## Crossfade

**Audio settings → Crossfade** (`ringnav_audioset`, stock's `playset_gapless` icon, fifth after the reorder below; `patch/crossfade.c`) reads `Crossfade: Off` or `Crossfade: 5 s` (`Q2POD XFADE` and `XFADESEC`, 1-10, default 5, in `config.ini`). It opens stock's Boot volume page re-dressed: `playset_bootvol_page_init` (`0x4b4a80`) binds `img_bootswitch`'s click (`on_bootvol_switch_onclick`), `img_dec`'s and `img_add`'s (`0x4b4624`, `0x4b45a8`) and `slider_bootvol`'s `EVT_VALUE_CHANGING`/`CHANGED` (`0x4b48f4`, `0x4b4300`), each with the window as context; `xfade_open` unbinds them with `widget_off_by_func` and binds its own, so Boot volume is never written. The title reads Crossfade and `view_bootvol` (the slider, the minus and plus and `label_vol`, "Off" or "5 s") is always shown: its slider runs `slider_set_min`/`max`/`step` 0, 10, 1 (AWTK takes doubles), 0 being Off, so the page needs no switch. That matters on iPod, where stock creates the title and `img_bootswitch` inside `view_navbar`, which `navbar_only` hides; the switch still toggles where it shows. Going Off keeps the length, which Centre brings back. `xfade_key`, from `ringnav` after `spot_key`, gives the page Centre (a single press toggles, a double press turns the screen off as on any page) and the wheel (a second a tick, down to Off).

**Settings order.** Playback and System are restacked by use after stock builds them and the payload adds its rows (`reorder`, `playset_order` and `sysset_order` in `patch/navigation.c`): Play Mode, EQ, Gain, ReplayGain, Crossfade, Gapless, Max and Default Volume, Balance, Filters, Memory Playback, Artists, the folder rows, Enlarged art, DSD and USB output; and Wireless, Display, Power, Date & Time, Buttons Lock, Key Tone, Network, Language, In-Vehicle, Boot to (with Rockbox), Update, Reset, About. Stock names each row's button by its table id (`"%d"`) and its click handler (`0x4b9364` for Playback) reads the id back from that name, so moving a row keeps its action; a page with an unexpected row count is left as built.

**Policy.** `xfade_poll`, from `playback_poll` each UI pass, writes the next change's fade in ms to `/tmp/q2xfade` (an `int`, made whole under `.tmp` and renamed like the visualizer's tap, then mapped shared), only when its inputs change: Crossfade on, stock's Gapless on (the byte `0xa3be54`, `mclGetGaplessMode`), and the next track another album's (`album_cmp`, so an album, a CUE image or an untagged folder stays gapless). The next track is `playback_next`: `playback_successor(1)` while advanced play runs, else `pos + 1` in modes 0 and 3, which is what stock preloads (`mclAutoChange` preloads under 6 s from the end, too late to decide on, so the poll predicts it instead). The first fade puts the PEQ filter in the chain (`peq_attach`) when PEQ is off, as the visualizer does.

**Fade.** The fade runs in `patch/peq_player.c`'s filter, after the PEQ and before the visualizer's tap. Each block reads the decoder's position, `written_audio_pts` (`0x44641c`, a leaf of `sh_audio` `mpctx+0x2c` and `d_audio` `mpctx+0x34`; `playing_audio_pts` at `0x42a134` subtracts the output's delay from it), and the length, `0xb10e84`, the whole seconds `{media-info}` reports (`mclGetPlayTime`). From `2 × fade + 2 s` before the end the filter keeps what comes in in a 4 MB ring and puts out half as many frames, oldest first, until the fade's length is held, then as many as come in: the decoder runs at twice real time meanwhile, and nothing is skipped or reordered. The next track's filter is a new instance (the player re-adds it at each file; each gets `player_state.id`), which mixes the held tail under its own first frames, `in × sin(p) + out × cos(p)` over the held length, so the sum keeps its power. Should the player keep one instance across the change, a position that starts over near 0 right after the end counts as the next track as well; the hold keeps the length it began with. A position jump over 1.5 s while holding is a seek and drops the held audio; so does a tail not followed within 3 s (stop) or followed at another rate or channel count. The hold is capped by the ring: about 10 s at 44.1 kHz stereo, 4.7 s at 96 kHz, 2.3 s at 192 kHz. While a fade is held, the elapsed time runs ahead by what is held, so it reaches the length as the next track fades in. DSD passes through the filter untouched, so a fade into or out of DSD does not happen. ponytail: a manual skip during the hold mixes the held tail into the chosen track; a rate change at the switch drops it.

Checks in `test/peq.py` (host build of the filter): the hold window, half-rate emission and order, the equal-power mix and its length, no fade asked, a seek while holding, another rate after, the same instance starting over, and an unknown length; `test/patch.py`: the row and its saved length.

## Resume

`ringnav_sleep` (both variants, the UI thread) polls at most once a second. It reads the queue's playing record (`queue_now`) and `player_playtime_and_length` (`0x514128`): elapsed and total track seconds, CUE-relative, and -1 while nothing plays. A track is long when its total is at least `RESUME_MIN_S` (20 minutes), or its extension is `.m4b` (case-insensitive) anywhere on the card, or it is under [Podcasts or Audiobooks](#podcasts-and-audiobooks), and its record has no CUE start or end (`+0x48`, `+0x4c`). A CUE track (either set) is long only when spoken (`.m4b`, or under those folders), so a music CUE image is left alone. Places are kept by the path's FNV-1a hash in a ring of `RESUME_SLOTS` (512, a 4 KB file), most recent first, as file seconds: a CUE track's place is its start plus its elapsed seconds, so a book's chapters share one place, and the same file played whole resumes there too. The ring is read from `/mnt/data/ringnav-resume` on the first long track and written whole, to a `.tmp` then renamed. That happens every `RESUME_SAVE_S` (60) seconds of movement, once the time stands still for two polls (a pause), and on a track change. A place within `RESUME_EDGE_S` (30 s) of either end of the file is forgotten. A CUE track saves nothing within its own first `RESUME_EDGE_S`, keeping the book's place, so a chapter played becomes the book's place once past its first 30 s; only the last CUE track (no end set) knows the file's end, where the book is finished and its place forgotten. A track change, `listen_key` (the path's hash with a CUE start mixed in, so moving to the next chapter counts), waits one poll before it counts, so the previous track's time never belongs to the new one. When a long track with a saved place first plays (elapsed at least 1 s) with under `RESUME_START_S` (5 s) elapsed, `player_seek_time` jumps there, as Scrub commits. A track paused at 0 waits for Play, so Memory Playback's paused boot does not seek, and its Location restore, already under way, is left alone. A CUE track never jumps when played: a chapter picked is played from its start. Instead the [Queue menu](#queue-menu) of a spoken CUE song row whose file has a place starts with **Resume** (`book_place`): it copies the page's songs (type 8) and plays them as a library queue (`play_folder(..., 0xf001)`, as Most Played) from the last chapter of that file starting at or before the place, with the seconds into it waiting for that chapter's `listen_key`, for up to 8 s. The poll seeks there once that chapter plays under `RESUME_START_S`, so the previous position the player still reports, or a queue that switches a poll or two late, does not consume it; the chapter already playing works the same way. With no place left at the pick, the menu says "Queue unchanged". The ring's format is unchanged, so places saved before stay valid: an earlier release's 32-slot file loads as the first 32 places, and an earlier build reads the first 32, the most recent, of the bigger one. A hash collision only means a wrong resume point.

## Books

**Books** is the last Local Music row (`media_find` kind 4, `assets/icons/local_books.png`, tan with an open book), for a top-level `Books` folder, case aside. `books_open` (`patch/books.c`) opens a runtime `books_page` (`CTX_DYNAMIC`) with two views:

- **List**: Coverflow's `page_list`: the folder's `.txt` and `.epub` files and those of its subfolders (one level, not dot files), by path, at most 500, each named by its file name without the extension. ponytail: an EPUB's `dc:title` is not read.
- **Reader**: a bare `view` (the sheet) the paint hook fills, and Photos' caption band. `books_paint`, called from `ringnav_paint` like `photos_paint`, sets the system default font at 20 px (`canvas_set_font(canvas, NULL, 20)`, as `draw_centred`) and white text over the black page, then lays out `BOOK_ROWS` (10) lines 26 px apart from y 6, 24 px in from either side, every line clear of the glass corners, with `canvas_measure_text` per character and `canvas_draw_text` per line. Lines wrap at the last space, else mid-word; a line break at the top of a page and a byte order mark are dropped; `\f` starts a new page. Text is UTF-8, and any byte that is not valid UTF-8 is read as Latin-1. The same paint finds the page before: pages laid out again from a line start up to 3 KB back until one reaches this one (`book_back`), so paging back may realign to a paragraph start. `ringnav()` hands the reader's keys to `books_key` before the surface lookup (the sheet is not a list): the wheel moves to the next or previous page, Centre toggles the caption (how far in, as a percentage of the file, and the title), and Return (the page's key-up, as Photos') goes back to the list, its bar on the book.

The file is read through a 32 KB window starting 8 KB before the page, read again once the page is within 4 KB of its start or 8 KB of its end, so no book is loaded whole. The page last read, a byte offset, is kept per book (FNV-1a of the path) in `/mnt/data/ringnav-books`: 64 key/offset pairs, the most recently read first, written whole through coverflow.c's `blob_io` when the reader closes, and reopened there.

**EPUB.** The first open converts the book on one pthread into `/mnt/mmc/.books/<fnv(path)>.txt` (through a `.tmp` and a rename), showing "Preparing…" in the caption; a 250 ms timer joins it, and later opens read the text at once. Leaving cancels between documents and joins. demo imports nothing from zlib (`libz.so.1` is loaded, but neither `inflate` nor `dlopen` is in its GOT), so `book_inflate` is a raw-deflate decoder after zlib's `puff`: stored, fixed and dynamic blocks, every length and distance checked against the output and the input. The zip's end record (in the last 64 KB) gives the central directory (2 MB at most); an entry is read by name through its local header, stored or deflated, 8 MB at most either way; encrypted and ZIP64 entries are refused. `META-INF/container.xml`'s `rootfile` `full-path` gives the OPF; each spine `itemref`'s `idref` is looked up in the manifest (`item`, any namespace prefix, either quote), and its `href`, relative to the OPF, `%XX` decoded and without a `#fragment`, is read. Images in the spine (`media-type` `image/…`) are skipped. `book_xhtml` turns each document into text in place: tags dropped; `p`, `div`, `br`, `li`, `tr`, `hr`, `dt`, `dd`, `h1`-`h6`, `blockquote` and `section` as line breaks (at most one blank line); `head`, `style`, `script` and comments skipped; `&amp;` `&lt;` `&gt;` `&quot;` `&apos;` `&nbsp;` and numeric entities as UTF-8; white space runs as one space. Documents are joined by `\f\n`, so each starts a page. A book with an `encryption.xml` naming a content document (DRM; obfuscated fonts alone are fine), or whose container, OPF or a spine document cannot be read, says "Can't open this book". ponytail: each itemref scans the manifest, quadratic in the items; an id index if large books prepare slowly.

Checks in `test/peq.py` (host build of `books.c`): inflate against zlib at every level and strategy, a short output and a truncated stream refused, garbage that never runs out of bounds; XHTML to text; EPUB conversion from stored and deflated zips with a prefixed OPF, a `%20` href, a fragment, a cover image and an empty document; obfuscated fonts against DRM, a missing container, truncated and bit-flipped zips, cancel; UTF-8 with the Latin-1 fallback; wrapping, `\f`, and paging back exactly in a short text and to a page reaching the current one in a long one. `test/patch.py`: the Local Music row, the list, the reader's lines (white, default font, inside the glass at every row), the wheel's pages both ways, the caption, Return, the saved page, an EPUB converted by the MIPS worker and read, and a broken one.

## Videos

**Videos** is the last Local Music row (`media_find` kind 5, `assets/icons/local_videos.png`, blue with a play screen), for a top-level `Videos` folder, case aside. It opens Books' page and list (`books_open(root, 1)`): `.mp4`, `.m4v`, `.mkv`, `.avi`, `.mov` and `.mpg` files, by path, one level of subfolders. A row (`play_video`) calls stock `player_stop` (`0x515b94`: hciplayer keeps its PCM, `hw:1,0`, open while paused), readies the headphone output on the DAC as stock's `player_start` does before each track (`dac_take`, shared with Spotify's `spot_take`: `config_outputchannel(g_headset_output, 2)`, which powers the DAC with its firmware in headset mode, or `mclSetDacPwr(1)` for a line out the DAC-off timer powered down; then PCM mode, unmuted, and the volume), then `fork`s and `execl`s `/usr/bin/q2video DEVICE PATH [VOLUME]`, the path a plain argument: nothing passes through a shell. `DEVICE` is `plughw:0,0`, the headphone DAC (the CS43131, the only ALSA card; there is no card 1), whose hardware volume (`mclSetVol`, ioctl `0xc0044d00` on `/dev/shanling_dac`) stays the music's. When `mclGetOutputWay` is 1 (Bluetooth) it is `plug:bluealsa`, the PCM hciplayer opens for that way (`0x439858`, string `0x88ed30`): demo writes `defaults.bluealsa { device "XX:XX:..." profile "a2dp" }` for the connected device to `/mnt/data/asound.conf`, which `alsa.conf` loads, so the name needs no address. There the volume is hciplayer's soft volume: `device_set_volume` (`0x4f44d4`) calls `mclSetBtVol(v, v)`, sending `{mcl-setvol\%d}` with `v << 8 | v`, and hciplayer's handler (`0x42c770`) calls its `mixer_setvolume` (`0x428744`), which sets an `af_volume` level of `0.1 + 0.018 (v - 50)` from 50, `v * softvol-max (20) / 10000` below, and removes the filter at 100 (no `snd_mixer` is imported, so the soft path is the one taken). So the payload passes the effective `headset_gain()` as `VOLUME` (full gain after accepted headset volume, otherwise `g_volume`, 0-100), and the helper scales its samples by the same curve (`bt_gain`, in 1/65536) and leaves the DAC's mute alone. With a USB DAC (2) `DEVICE` is `usb`, which the helper turns into `plughw:N,0` for the card `/proc/asound/cards` lists as `USB-Audio` (card 1 behind the headphone DAC's 0, as stock's `mclUsbAudioSetVol(…, "hw:1")` has it; hciplayer's `hw:2,0` string, `0x43975c`/`0x88ed40`, is no card on the Q2), and the plug converts the helper's 48 kHz stereo to what the DAC takes. Its volume is `device_set_volume`'s: `mclUsbAudioSetVol(v, v, "hw:1")`, or 100 when `g_usbvol_mode` (Audio settings' USB volume) is 0, fixed. That sets the DAC's own volume control; a DAC without one leaves `USB_MIXER` (`0xa3be6c`, no symbol) at -2 and sends hciplayer `{mcl-softvolflag\1}`, whose set-volume handler then applies the same `mixer_setvolume` curve as Bluetooth's. So `VOLUME` is plain `g_volume` (the helper's `bt_gain`) only for a variable volume on a DAC without its own control; otherwise it is `h` and the volume, which the helper shows on its bar and never applies.

While the helper runs, demo's loop goes on (timers, threads, the status bar) but `ringnav_input` drops every input event before the window manager, sending a key's release (`0x114`) to the helper as a datagram on its `AF_UNIX` socket `/tmp/q2video.sock` (`video_key`): Return `q`, Play/Pause `p`, the side buttons 222/223 `b` and `f`. The wheel is the volume, as on Now Playing: a tick steps `g_volume` as stock's `volume_dialog` keys do (`0x4a2044`: by 1, up only below 100 and `g_maxvolume`, down to 0), calls `device_set_volume(v, 1)` (the DAC's `mclSetLocalVol` ioctl, so the DAC follows at once, and for Bluetooth `mclSetBtVol`, so hciplayer has it after) and `write_int_config(v, "PLAYSET", "VOLUME")`, without stock's dialog, and sends `v` and the volume byte, at an end too. Centre toggles the wheel to seeking (`s`, then `b` and `f` per tick) and back (`v`); `video_poll` also puts it back on the volume `SCRUB_MS` (3 s) after the last tick or Centre, like Now Playing's scrub. And `ringnav_wm_paint` skips the window manager's paint. `video_poll`, from `ringnav_sleep`, calls `waitpid(WNOHANG)` every pass, meanwhile `reset_poweroptions_timer(1, 1, 1)` (`0x4f43dc`, the screen, standby and auto-power-off counters `on_wm_idle_status` and `check_to_poweroption` count down) and zeroes `g_dacoff_time`; at the helper's end it closes the socket and repaints the whole screen. Music stays stopped. A video picks up where it was stopped: `play_video` writes the second kept for its path (FNV-1a, in Books' `BOOK_MARKS` ring, through the same `mark`) to `/tmp/q2video.place`, which the helper reads as its first `-ss`; on its end it writes there the second a Return left it at (`resume_at`: 0 within `EDGE_S`, 30 s, of either end, as [Resume](#resume)'s `RESUME_EDGE_S`, and 0 when it played to the end), and `video_poll` keeps that for the path, unless it and the start were both 0, so a video never resumed takes no slot from the books. A seek still pending at the Return counts.

**q2video** (`patch/video.c`, about 10 KB) is linked by `tools/build.py` against the rootfs's own `libc-2.28.so`, `libpthread` and `libasound.so.2` (no MIPS sysroot: the file declares what it uses), `nan2008`, `fp64` and `/lib/ld-linux-mipsn8.so.1` as the stock binaries, with its own `__start` like glibc's. It runs stock `/usr/bin/ffmpeg` (FFmpeg 4.2): `-ss` the start, `-vf scale=375:320:force_original_aspect_ratio=decrease:flags=fast_bilinear,format=bgra,pad=375:320:(ow-iw)/2:(oh-ih)/2,transpose=clock` (the picture fitted into the landscape 375 × 320 view, then turned clockwise onto the portrait framebuffer, as the boot logo is stored), `-r 25 -f rawvideo pipe:3`, and `-ac 2 -ar 48000 -f s16le pipe:4`. `/dev/fb0` is 320 × 375, 32 bpp with red at bit 16 (ffmpeg's `bgra`) and two pages: `soc_fb.ko`'s `init_var_info` gives every 32-bit format red 16, green 8, blue 0 and `yres_virtual` = `yres` × `layer0_frames` (2 in `module_driver/soc_fb.sh`, `is_rotated=0`); stock `display_logo` (`0x400bf0`) refuses under 18 bpp and stores each pixel as the word `0xff000000 | R << 16 | G << 8 | B` (`0x400f2c`), the 320 × 375 JPEG unturned; demo's AWTK flush thread pans between the two pages (`FBIOPAN_DISPLAY` at `0x6265bc`, then `FBIO_WAITFORVSYNC`). The helper exits without drawing if `FBIOGET_VSCREENINFO` reports anything else. A thread writes the sound with `snd_pcm_writei` in 512-frame chunks (200 ms buffer) and keeps the frames heard (written less `snd_pcm_delay`); frame n goes to the framebuffer at n / 25 s of that clock, a whole frame late is dropped, and it draws the page demo is not showing and pans (`FBIOPAN_DISPLAY`), panning back to demo's page at the end. The video pipe is 4 MB (`F_SETPIPE_SZ`), so ffmpeg is paced by the sound. A `v` sets Bluetooth's gain to `bt_gain` of its volume. `s`, `b`, `f` and `v` show a bar for 1.5 s (`OVERLAY_MS`), drawn on the page after each frame's copy and before the pan, and redrawn with the next frame when paused: `BAR_H` (8) px high, `BAR_Y` (22) px above the picture's bottom and `BAR_X` (40) px in from its ends, clear of the 80 px glass corners, white for the volume of 100 or the position (start plus frames shown plus pending seek) of the length, black for the rest, by byte fills (white and black in BGRA). The length comes from a second `ffmpeg -nostdin -hide_banner -i PATH` started at once, its stderr read on the main loop's poll until it ends (or 4 KB) for `Duration: HH:MM:SS`; without one the position bar is not drawn. Pause holds the writer (the sound buffer plays out, then the clock stops); a seek restarts ffmpeg once 400 ms after the last tick, at the position plus 10 s per tick; without a sound stream ffmpeg fails at once and it runs again silent on a monotonic clock. After hciplayer's stop it opens the PCM (retrying 2 s; bluealsa takes one client per PCM, so this also waits for hciplayer's close), sets the DAC to PCM (`0xc0044d1b`, 0, as hciplayer does per PCM track, so a DSD track's mode is undone) and unmutes it (`0xc0044d1f`, 0); at the end it mutes it again, as a stopped hciplayer leaves it. ponytail: the frame rate is fixed at 25 and decoding is software, so sources much above the screen's size can fall behind; a smaller encode then plays smoothly.

Checks in `test/peq.py` (host build of `video.c`): ffmpeg's argv with and without sound, the frame pacing, Bluetooth's gain curve and sample scaling, the `Duration` parse, `resume_at`'s edges, and the bar's pixels on a padded-line frame. `test/patch.py`: the Local Music row, the list, the child's `execl` argv after `player_stop`, the DAC power-on, Bluetooth's device and volume, silent USB, every key's datagram, the volume steps and their limits through `device_set_volume` and `write_int_config`, Centre's seek mode and its timeout, no other input or paint while playing, the held timeouts, and the end.

## Spotify

**Spotify** is Streaming's row after stock's (`ringnav_stream`, after `stream_page_init`'s rows in `scroll_view_streamsset`, a `library_into` row with `assets/icons/stream_spotify.png`, Spotify's logo as a 52 px palette PNG with `list_tidal`'s inode metadata). It opens the browser (below; without `librespot` on the card, `spotify_page` saying so), a runtime window (`patch/spotify.c`), for librespot, a Spotify Connect receiver built from the [q2-librespot](https://github.com/DiamondBond/q2-librespot) fork (branch `shanlingq2`; hard-float, linked against the stock glibc, 19.5 MB, so it stays on the card). Nothing of it is in the firmware: the card's `/mnt/mmc/.spotify/` holds `librespot`, its launcher `run`, the sink `aplay.sh`, the saved login `cache/` and the logs.

**Starting.** `spot_launch` runs `system("/bin/sh /mnt/mmc/.spotify/run")` once per boot, when the row is first pressed, and only then: until it has, `spot_poll` returns at once and nothing reads the card or the state file. The login (`cache/credentials.json`, written after the first Connect handoff) only saves the phone's pick. `run` passes `--cache-size-limit` from `.cache-size` ([Streaming configuration](#streaming-configuration)), `2G` without it. `run` backgrounds a loop that restarts librespot after any exit, waiting 5 s and doubling to a minute while runs keep failing (mDNS needs Wi-Fi up), and leaves the loop's pid in `/tmp/q2-librespot`, which also makes a second run exit. librespot's process is not demo's child, as bluealsa's isn't. Once it has played, `SPOT_IDLE_MS` (30 s) without playing (paused, stopped or handed to another device) while the browser is shut makes `spot_poll` stop it as Home's Rockbox row does (`spot_stop`: the loop's pid, `killall -9 librespot aplay`, the pid file, the state file and `SPOT_OUT` removed), so the keys are local music's again; the row starts it again. Before it has played, the wait is `SPOT_CAST_MS` (150 s), time to cast to the Q2 from the phone; it counts from the launch or the last poll with the browser open, whichever is later. An open browser (pairing prompt and Now Playing on it included, and so any request in flight) restarts the wait every poll, but holds no timer and no DAC: only playing does (`spot_take`). Without `librespot` on the card `spotify_page` says so and nothing runs.

**Contract.** librespot runs with `--backend subprocess --device "/bin/sh ./aplay.sh" --volume-ctrl fixed --initial-volume 100 --control-socket /tmp/q2-librespot.sock --status-file /tmp/q2-librespot.state` (the last two are the fork's):

- The status file is rewritten whole (a `.tmp`, renamed) on each player event: `state=` `none` (no Connect session: the phone hasn't chosen the Q2, or chose another device), `stopped`, `paused` or `playing`; `track=` (the Spotify id), `title=`, `artist=` (joined by `, `), `album=`, `duration=` and `position=` in ms, `at=` the `CLOCK_MONOTONIC` ms the position was taken at, and `cover=1` once `/tmp/q2-librespot.state.jpg` holds this track's cover, which librespot fetches itself over its own TLS (the smallest Spotify image at least 160 px wide: 300 px). The payload does no TLS.
- The socket takes `AF_UNIX` datagrams, sent `MSG_DONTWAIT` as Videos' are: `p` play/pause, `P` play, `s` pause, `n` next, `b` previous, `S` and a position in ms to seek. librespot ignores them without a session.
- The subprocess sink starts `aplay.sh` when playback starts and kills it when it stops, pause included, so the DAC's PCM is free while librespot is paused. `aplay.sh` is the stock `aplay -D plughw:0,0 -f S16_LE -r 44100 -c 2`, retried for 3 s: aplay opens the PCM before it reads its input, so a busy PCM costs no audio. Each try first reads `/tmp/q2-librespot.out` (`SPOT_OUT`): when it holds a device and a volume, it runs `/usr/bin/q2video -s DEVICE VOLUME` instead (below). Without the file, which older Q2 Pods never write, it is aplay as before.
- **Output.** Every poll `spot_output` asks `output_device` (books.c, Videos' and Internet Radio's choice through `video_start`) for the output in use: none on the headphone DAC, `plug:bluealsa` with `headset_gain()` for Bluetooth (`mclGetOutputWay` 1), `usb` with `g_volume`, or `h` and it when the DAC applies the volume, for a USB DAC (2). When the line changes it writes `DEVICE VOLUME` to `SPOT_OUT` (a `.tmp`, renamed) or removes the file, and sends `v` and the effective gain to `/tmp/q2sink.sock`. `q2video -s` opens the device at 44.1 kHz, S16 stereo, with Videos' `sound_open` (retrying 5 s while hciplayer lets go), plays stdin through Videos' writer at `bt_gain` of the volume, as hciplayer's soft volume would (the DAC's mute is left alone), and takes `v` and `q` on that socket as radio's helper does. It ends with its input (the sink's kill closes librespot's pipe) or when a write fails even after `snd_pcm_recover`, a headset gone: librespot's subprocess sink then restarts `aplay.sh` once, which reads the file again. ponytail: otherwise an output switched while playing takes over at the sink's next start (pause and play), as Videos and Internet Radio keep their device until they end.

**Polling and power.** `spot_poll`, from `ringnav_sleep` every `SPOT_POLL_MS` (500 ms), reads the file and parses it when it changed. On the change to `playing` (`spot_take`) it does what stock's AirPlay page does for its receiver (`airplay_page_init`, `on_airplayset_onclick`): `player_stop` unless hciplayer is stopped (it holds the PCM even paused), `config_outputchannel(g_headset_output, 2)` (what a headset insert runs: `mclSetHeadsetMode`, `mclSetDacPwr(1)`, which also loads the DAC's FPGA firmware, and `g_dacoff_time` 0), `mclSetPcmMode`, `mclSetMute(0)` (`player_stop` mutes) and `device_set_volume(g_volume, 1)`. With Bluetooth or a USB DAC (`mclGetOutputWay` 1 or 2, `g_headset_output` 2 or 3) it skips all of that, as `video_start` does: the sink plays there itself (Output, above), and the DAC stays as stock's `config_outputchannel` left it, off (`g_dacoff_time` -1, or counting from 0 after a key or local playback, which only powers it off again). A way left at 2 with a jack as `g_headset_output` (a USB DAC pulled while hciplayer was stopped) still gets `dac_take`, which also puts the way back; and when the output returns to the headphone DAC mid-play, `spot_output` readies it once for the sink's restart there. While `playing`, every poll calls `reset_poweroptions_timer(1, 1, 0)` (`0x4f43dc`: its arguments are standby, auto power-off and the backlight, in that order) and zeroes a counting `g_dacoff_time`, so neither standby nor `check_dacoff_state` ends playback, while the screen still turns off on its timer. On the headphone DAC the volume is the DAC's own: librespot's is fixed at 100%, and `device_set_volume` (stock's volume dialog, the screen-off wheel) sets the DAC with `mclSetLocalVol` whether or not hciplayer plays. ponytail: Low Power still takes CPU1 offline with the screen off; librespot decodes on one core, and an exception like Videos' is the upgrade if that falls short.

**Keys.** `ringnav()` hands Play/Pause, previous and next (171, 222, 223) to `spot_media` right after stock's key-lock filter (`on_wm_keyup_before_fun`), on any page and with the screen off, while Spotify is the active source: playing or paused, and no local track has played since. They become `p`, `b` and `n`, and stock's own key-up never sees them. On the page Centre works as on Now Playing's [scrub](#scrub-ipod) (`spot_key`): a release arms the same `DOUBLE_CLICK_MS` (250 ms) timer (`center_press`, shared with Now Playing), and a second one before it ends starts a scrub; the wheel then moves it `SPOT_STEP_MS` (5 s) a tick and the bar turns white, and a centre press (at once, swallowing a quick second one, as on Now Playing), Return or `SCRUB_MS` without a tick seeks there with `S`. Outside a scrub the timer, a single press, replays the release to stock `on_wm_keyup_fun`, so the screen turns off. Otherwise the wheel is stock's volume and `spotify_page` is not in `contexts.inc`, so `ringnav()` leaves it to stock.

**Hand-over.** Local music → Spotify is `spot_take` above. Spotify → local music: `mclStartPlayer` (`0x5ad6ac`), which every local track's start runs before hciplayer opens the PCM, is hooked (`ringnav_start_player`). With librespot playing, `spot_yield` sends `s` and waits, 20 ms at a time up to `SPOT_YIELD_MS` (1.5 s), until the file no longer says `playing`. The fork's sink stops (aplay killed and reaped) before the `Paused` event, so the PCM is free once it does. The keys are local music's again from then on. Home's Rockbox row kills the loop and librespot (`/tmp/q2-librespot`'s pid, `killall -9 librespot aplay`), as Rockbox takes ALSA.

**Page.** `spot_open` builds Now Playing's layout from `tools/ipod.py`'s `NP_*` in both variants: "Spotify" in the top row with a play or pause glyph at its end, the art 166 px at x 16, y 50, the title (22 px white), artist and album (16 px `#AAAAAA`) in a 165 px column at x 194, the bar at `NP_BAR` and the times under it. The art is librespot's cover sized once a track by Coverflow's `thumb` (`toolsThumbSpecCover` under `parse_cover_mutex`) to `/tmp/q2spot.jpg` and loaded with its `image_show`, `default_album_big` (Legacy) or `default_album_flow` (iPod) until there is one; iPod rounds its corners as Now Playing's (`paint_cover`). The position is `position + (now - at)` while playing, clamped to the duration. A 250 ms timer, idle with the screen off, writes the times when the second changes and repaints the bar, which `spot_paint` draws as Now Playing's capsule: `TRACK_COLOR` with the played part in the accent's light tone (iPod) or stock red (Stock). The remaining time is whole seconds less whole seconds, as Now Playing's. Only a `login` reply or a sign-out shows "Open Spotify on your phone / and choose Q2"; a playing or paused track, or any `ok` reply, confirms the login, and `state=none` makes it unknown again. A successful play shows "Loading…" until a track plays: the one asked for, or any other than before it (a relinked id). After `SPOT_WAIT_MS` (15 s) it says "Playback didn't start", without sending play again, until any track plays. The three labels scroll without focus or an ellipsis and restart when their text changes; `field` cuts only at a UTF-8 character boundary. It sits on the browser, so Return goes back to the list it was opened from. ponytail: the cover is sized on the UI thread, one decode a track; a worker if it stutters.

**Browser.** `spotbrowse_page` (`CTX_DYNAMIC` in `contexts.inc`, so the wheel moves its rows) is one `page_list` rebuilt per level, as Internet Radio's, its rows' clicks run from a timer. A level is a Q2SPOT/1 request ([librespot.md](librespot.md#browsing-protocol-q2spot1)): its op, its arguments and cursor (escaped, `spot_escape`) and its reply, cut in place by `spot_reply` into the header's 4 fields and 6 a row (at most 50), unescaped; a bad escape, `%00`, a NUL, a line of the wrong width or too many rows makes it malformed. IDs, URIs and cursors are sent back exactly as received. The base level asks `account`: `ok` shows the menu (Now Playing, Queue and Playback Settings only with a track), `login` the pairing prompt ("Open Spotify on your phone and choose Q2", "Both on the same Wi-Fi"), which asks again every `SPOT_PAIR_MS` (2 s) and becomes the menu once paired. Liked Songs, Playlists, Albums and Artists list 64 px rows (title over subtitle); an album, playlist or artist row opens its own level (an artist's top tracks, then its albums), and a non-empty cursor adds **More…**, a level of its own, so Back returns to the page and the row left. Up to `SPOT_DEPTH` (8) levels are kept, the oldest past the base dropped; only the top `SPOT_KEEP` (3) keep their replies (64 KB each at most), and Back to an older one fetches it again. Search lays peq_ui.c's T9 edit over the title; its OK with text opens Tracks, Albums, Artists and Playlists for the term, and empty text or the box's blur leaves the menu as it was. A track row sends `play CONTEXT POSITION URI` (`play URI` without a context; a Queue row `skip POSITION URI`) and opens Now Playing once it is `ok`, else toasts the message. Play/Pause held on a track row (`ringnav_keylong` → `spot_hold`) sends `enqueue URI`, its release latched as the radio's, and toasts "Added to Queue" or the message. Playback Settings shows shuffle and repeat (Off, All, One); a press sends the next value and reads them again. Account shows the name and Premium, and Sign Out asks first; after `signout` the pairing prompt returns. Loading ("Loading…"), empty ("Nothing here", unless a cursor offers More…) and errors are page states: the backend's message as the title, with **Retry** for `offline`, `throttled`, `error` or no usable reply. Any `login` reply returns to pairing.

**Worker.** `request` writes `Q2SPOT/1`, the id (`wk.id`, never reused) and the op into a 64 KB buffer and starts `worker` on a pthread: an `AF_UNIX` `SOCK_STREAM` (2, MIPS numbering) to `/tmp/q2-librespot.browse.sock`, the request sent `MSG_NOSIGNAL`, the write side shut (`spot_shut`, the o32 `shutdown` syscall 4182, since demo imports no `shutdown`), then `select` 100 ms at a time and `recv` into the same buffer until EOF, `SPOT_WAIT_MS` (15 s) or a cancel; more than 64 KB fails. One request at a time: a new one, Back from a loading level or the page's close cancels the one before and joins it within 100 ms. The page's 250 ms timer takes the finished reply on the UI thread; one whose header doesn't echo the id, or for a level since left (`level.id`), is dropped. Actions (`play`, `skip`, `enqueue`, `shuffle`, `repeat`, `signout`) are never sent again by themselves. No socket within `SPOT_OLD_MS` (3 s) of librespot's start, or `SPOT_SIGNOUT_MS` (15 s) after a sign-out (librespot exits and its launcher restarts it), is librespot starting: "Loading…" (or the pairing prompt) asks again every 500 ms. After that, a state file means an old add-on: Now Playing and "Update Spotify on the card / to browse on the Q2", still asking every 2 s. Without either, "Spotify isn't running" with Retry. ponytail: a title is cut at 255 bytes by the backend and a search term at 63 by the page; nothing is cached across opens.

Checks in `test/peq.py` (host build): `spot_reply` on escapes in any case, UTF-8, a short header, every malformed shape and the row limit; `spot_escape` and its bounds. Checks in `test/patch.py`: the row and its icon, the page without librespot (nothing starts), the start once per boot from the row and never without it, saved login or not, the session prompt, `spot_take`'s calls and their order and Bluetooth's exception, `SPOT_OUT` and the sink's volume on Bluetooth and its removal on the DAC, the held timers, the art, the labels moving on from `at`, every label inside the glass, the bar's rectangles and colour, the keys on another page and their return to local music, `mclStartPlayer`'s wait and its limit, the scrub and Return; the idle stop only with the browser shut. The browser against a fake backend on the socket: the first request's bytes, the menu with and without a track, loading, errors with and without Retry, empty pages, More… on an empty page, a wrong id, a bad escape and an oversized reply, playlists by URI, tracks played in their context (with their URI) or alone and Now Playing only on `ok`, More… and Back to the row left, Back while loading, an artist's and album's pages and a refetched evicted level, pairing and its polling, an old add-on and a missing librespot, search's empty, left and escaped terms, Add to Queue on hold and its failure, Queue's skip, Playback Settings and an unrepeated failure, Sign Out's confirmation, the restart after it, a lost login, and the idle stop after the browser shuts and the relaunch.

## AirPlay

Stock's receiver is `/usr/bin/shairport`, Shanling's Shairport 1.1.1 (`1.1.1-22-shanling`): AirPlay 1 (RAOP) only, with its own mDNS responder, started and stopped by demo (`airplayStartService`, `airplayStopService`) from Network service's switch (`on_airplayset_onclick`, `0x51e8f0`), with its now-playing page `airplay_page`. Streaming's **AirPlay** row (`ringnav_stream`, stock's `netservice_airplay` icon) only opens `systemset/netservice_page`. ponytail: the row doesn't toggle the service itself; stock's `airplay_switch` (`0x50ef44`) is the way in if it should. AirPlay 2 would be a shairport-sync 4.x add-on with nqptp, an add-on on the card like librespot.

## Internet Radio

**Internet Radio** is Streaming's last row (`ringnav_stream`, `assets/icons/stream_radio.png`, a broadcast glyph on coral, 52 px palette PNG with `list_tidal`'s inode metadata). It opens `radio_page`, a runtime window (`patch/radio.c`, `CTX_DYNAMIC` in `contexts.inc`, so the wheel moves its rows), one `page_list` rebuilt per level: the menu (Now Playing, when a station has played this boot or `/mnt/mmc/Radio/.last` exists; Favourites; Featured; Top Stations; By Country; By Genre), a country or genre list, and a station list. Rows rebuild the page from a timer (`later`), never inside their own click. Return goes up a level, from a "Loading…" or failure caption back to the list it covered, and from the menu back to Streaming. Each level keeps its selected row.

**Lists.** Favourites are `/mnt/mmc/Radio/favourites.m3u`, then every other `.m3u` and `.pls` there, read whole and parsed as one text (`playlist`): `#EXTINF:…,NAME` names the next line, `FileN=` is a URL and `TitleN=` names the one before; a line without `://` is no station. Favourites start empty: opening the page only creates the `Radio` folder. The six built-in stations (`STARTERS`, each checked against stock-like ffmpeg) are Featured, parsed from the payload. Search is the page's pull-down ([Pull-to-search](#pull-to-search)) on any level: `radio_search` lays a T9 edit (`edit_create`, shared with the EQ editor's value) over the title and focuses it for the keyboard; its OK (`EVT_VALUE_CHANGED`) fetches `/m3u/stations/byname/TEXT` (%-encoded, a substring match), and an empty result says "No stations", and Return goes back to the level it was pulled over. Empty text, or the box's blur (`EVT_BLUR`, `0x10f`) without a search, rebuilds the page as it was. An empty OK closes the keyboard with neither event, so the keyboard's OK (`EVT_IM_ACTION`, `0x13a`) runs the same handler. Return empties and blurs the box, which shuts the keyboard before the box is destroyed: destroying it under an open keyboard crashes demo. The directory is [radio-browser.info](https://api.radio-browser.info)'s round-robin `all.api.radio-browser.info`, fetched by `fetch_worker` on a pthread through demo's libcurl, over verified TLS with the firmware's `/etc/scrobble-ca.pem` (ISRG Root X1 signs it), 10 s to connect, 30 s in all, at most 256 KB: Top Stations is `/m3u/stations/topvote/100?hidebroken=true`, By Country `/csv/countries?order=stationcount&reverse=true&limit=60` then `/m3u/stations/bycountrycodeexact/CODE`, By Genre `/csv/tags?…` then `/m3u/stations/bytagexact/TAG` (%-encoded, `url_escape`), each with `?order=votes&reverse=true&limit=100&hidebroken=true`. The m3u is the favourites' parser's; the CSV (`choices`) is read from each line's end, so a quoted name may hold commas. Without Wi-Fi (`get_wifisignal`) the page says "No Wi-Fi"; a failed fetch "Directory unavailable". Return while loading sets a cancel flag that the transfer's progress callback returns, so the join takes at most about a second. A list holds `RADIO_MAX` (200) entries.

**Favourites.** Play/Pause held on a station (`ringnav_keylong` → `radio_hold`, the row from the list's `_ringnav_index`, or on Now Playing the station playing) rewrites `favourites.m3u` (a `.tmp`, synced and renamed) without it when its URL is there, else with it appended, and toasts which; its release is latched as the queue menu's (`st.qm_press`), so it does not stop the radio. A file already at `RADIO_MAX` is never rewritten, so nothing past it is lost.

**Playing.** A station (`radio_play`) copies the list it is in, so the side buttons step through it later, stops a playing q2video, pauses librespot (`spot_yield`), and starts `/usr/bin/q2video -r DEVICE URL [VOLUME]` through `video_start` (books.c), Videos' own output choice: `player_stop`, the headphone output readied (`dac_take`), `plughw:0,0`, `plug:bluealsa` or `usb`, and the volume for Bluetooth's and soft USB's gain. The station goes to `/mnt/mmc/Radio/.last` as a one-entry `.m3u`. The keys and their output stay demo's: `radio_poll`, from `ringnav_sleep` every 500 ms while it runs, reads `/tmp/q2radio.state`, reaps it (`waitpid(WNOHANG)`), calls `reset_poweroptions_timer(1, 1, 0)` and zeroes a counting `g_dacoff_time`, as Spotify's poll does, and sends `v` and the volume byte on `/tmp/q2radio.sock` when `g_volume` changes, so stock's volume (wheel, dialog, screen off) reaches the soft gain. `radio_media`, next to `spot_media` after stock's key-lock filter, takes Play/Pause (stop, or play again), 222 and 223 (the previous or next station, round the ends) on any page while the radio is the active source: it played last and no local track, video or Spotify has played since. Stopping (`radio_halt`) sends `q` and waits up to `RADIO_QUIT_MS` (1.5 s), then `kill -9` on its pid (librespot also uses q2video), and removes the state file. `mclStartPlayer`'s hook, `play_video`, `spot_take` and Home's Rockbox row call `radio_stop`, which also hands the keys back. Nothing starts at boot.

**q2video -r** (`radio` in `patch/video.c`) opens the PCM and readies the DAC as Videos does (`sound_open`), then runs stock ffmpeg with `-loglevel verbose -icy 1 -reconnect 1 -reconnect_streamed 1 -rw_timeout 15000000 -i URL -vn -ac 2 -ar 48000 -f s16le pipe:4` (HTTPS works: ffmpeg's `tls_verify` is 0), the sound to the same writer thread, its stderr read a byte at a time on the main loop's poll. libavformat's http logs `Metadata update for StreamTitle: …` only at verbose; the input dump gives `icy-br` and `Stream #0:0: Audio: CODEC`. `meta` takes a line's value after `KEY :`, so `icy-notice2 : … Network Audio Server` is no codec. The state file is rewritten whole (`.tmp`, renamed) on each change: `state=` `connecting`, `playing` (once the writer has played a frame) or `error`, `title=` (the StreamTitle, which the page splits at `-` into artist and song), `codec=` (upper case), `bitrate=` (kbit/s), `error=` (when `sound_open` found no device: `open:` or `params:` and `snd_strerror`'s reason, which the page shows as "Can't play: …"; Bluetooth and USB get 50 tries, 5 s, the DAC 20, at open and again at `snd_pcm_set_params` while it is busy, since bluealsa claims its PCM there; or `write:` when a write fails past `snd_pcm_recover`, which ends that ffmpeg run, as it ends Spotify's sink; Videos drop such a write instead, so their picture goes on) and `at=` (`CLOCK_MONOTONIC` ms the sound started, for the elapsed time). When ffmpeg ends anyway it starts again after 1 s, 2 s, … up to `RADIO_TRIES` (5) starts in a row without sound, then writes `state=error` and exits. A start with no frame written after `RADIO_SILENT_MS` (20 s) means the output is stuck (the writer may be blocked inside ALSA, so it can't be joined): it writes `state=error` with `error=no sound from the output` (or the writer's), kills ffmpeg and exits, so the page never stays on "Connecting…". `q` kills ffmpeg, unlinks the state, closes the PCM and mutes the DAC. No FM: the Q2 has no tuner (the device tree's only i2c device is the axp2101, and stock hciplayer was built with `--disable-radio`).

**Page.** `radionp_page` has Spotify's Now Playing layout: "Internet Radio" above, the row's icon unscaled in the art box, the station's list name, the StreamTitle's artist and song, then the codec and bitrate ("Connecting…", "Stopped", "Can't play: REASON" or "Can't play this station" instead). Local Now Playing's heart sits at its place (x 320 in Legacy, 303 in iPod, y 176, 50 px, `play_fav` / `play_unfav` centred): filled when the station playing is in `favourites.m3u`, which is read again only when `rd.serial` changes (each start and each toggle), and a tap toggles it as the held Play/Pause does (`fav_toggle`), with the same toast and the elapsed time, refreshed on a 500 ms timer idle with the screen off. It is not in `contexts.inc`, so the wheel is stock's volume and Centre stock's screen toggle. ponytail: no station logos; the directory's m3u has none, and a logo would cost another fetch and a decode per station.

Checks in `test/peq.py` (host builds): `meta` on ffmpeg's lines; `playlist` on CRLF, BOM, radio-browser's extra tags, `.pls` keys and the limit; `choices` on both CSVs and quoted commas; `url_escape`. `test/patch.py`: the row and its icon, empty favourites, Featured, a 1.0.1 seed removed and an edited one kept, the pull-down's search box, its query, its empty result and its cancel, the pull gesture on `radio_page` in both builds, the headphone output readied before the fork, the error's reason, the save from Now Playing and its heart, the favourites from every playlist, the child's `execl` argv after `player_stop`, `.last`, the page's labels connecting and playing, the held timers, the volume datagram, the media keys and the side buttons round the ends, `mclStartPlayer`'s hand-over, the kill after `RADIO_QUIT_MS`, the error, the favourites toggle and its latched release, Top Stations' fetch and TLS options, No Wi-Fi, genres with an escaped tag, countries by code, a failed fetch and Return through every level.

## Tidal cache

Stock's Tidal stream thread (unnamed, after `tidalGetFavoritesIdsThd` at `0x4863a0`) waits for `tidalfurlstart`, which `get_tidal_trackurl` sets after copying the record's song id into `tidalsongid`. It copies that id to its own `malloc` in `$s2` (`0x48647c`), sets `tidalStreamingLevelNow` from `tidalStreamingLevelNext` (at most 3), and asks `playbackinfopostpaywall` for that quality. It then base64-decodes the manifest (`toolsBase64Decode`) and passes its `urls[0]`, a direct file URL, to `mcl_tidalStartPlayer` (`0x5ad240`, called only at `0x486d88`), which sends it to hciplayer. A skip during the fetch rewrites `tidalsongid` but not the thread's copy.

`mcl_tidalStartPlayer` is hooked by `tidal_start` (`patch/tidal.c`), two instructions that pass `$s2` on as the song id; the build pins the `$s2` set-up and the call. With the extension of the URL's path (`.flac`, or `.mp4` kept as `.m4a`, which stock's file lists take), the card's `/mnt/mmc/.tidal/<id>-<quality> <artist> - <title><ext>` (`tidal_name`: the queue row with that id at `REC_TIDAL_ID` names it; FAT's reserved characters become `_`, and a long label is cut at a whole UTF-8 character) plays in the URL's place when it exists, found by its `<id>-<quality>` prefix and extension. Otherwise the URL plays, and a detached pthread downloads it with demo's libcurl to `.tmp`, flushes and syncs it, and renames it into place on HTTP 200. A skip (a `tidal_play` with another id; a re-fetch of the same id leaves its download running) or Stop aborts it from curl's progress callback, and one under 1 KB/s for 30 s gives up, so the `.tmp` is removed. Stop is inferred, not signalled: the callback reads stock's play status (`mclGetPlayStatus`, 1 stopped) and aborts once it has read stopped for `TIDAL_STOP_MS` (3 s) running, so the stopped state between queued tracks keeps the copy; ponytail: a stream that sits stopped longer than that before it plays drops its copy (cached on a later play). Only one download runs at a time: a track that starts while a skipped one's transfer is still ending leaves its URL as the job the same thread takes next, the latest track's only, and none is queued below `card_space`'s 16 MB. After each download the oldest files by mtime are removed until `.tidal` holds at most the cap chosen in [Streaming configuration](#streaming-configuration) (2 GB by default), read once per trim. Peer verification is off: the firmware's CA bundle lacks Tidal's CDN roots, and hciplayer streams the same URL unverified (ffmpeg's `tls_verify=0`). Only the URL sent to the player changes; the queue record, art and Now Playing are stock's. The API request still runs first, so a cached track started from Tidal's pages needs Wi-Fi but streams nothing. **Streaming → Tidal Downloads** (`tidal_downloads` in navigation.c) lists `.tidal` through `toolsLoadDirectory`, newest file first, by the label after the prefix, and folder-plays a row as local music, so it needs no Wi-Fi; its page name starts `tidal_`, so the playback keys stay with it (`media_focused`). ponytail: oldest download goes first (demo imports no `utime` to touch a replayed file); a `.tmp` left by a power-off stays until that track is cached again.

Checks in `test/peq.py` (host build): `tidal_ext` on a query string, a dot only in the query, a trailing dot and an extension too long for the buffer; `trim`'s eviction at 2 GB, 4 GB and 512 MB caps and a failed `unlink`.

## Streaming configuration

Streaming's last row, **Configuration** (`stream_config` in navigation.c, `stream_config.png`: stock's `system_netservice` with `list_tidal`'s inode metadata, resized on iPod as the other Streaming icons), opens `streamconf_page`, a `page_list` of three rows. It and Tidal Downloads are listed in `patch/contexts.inc` (`CTX_DYNAMIC`), so the wheel moves the selection and Centre presses the row, as on the other payload lists.

**Cache sizes.** Tidal Cache and Spotify Cache step through 512 MB, 1 GB, 2 GB, 4 GB and 8 GB (`512 << i` MB) on each press. Each is a file, `.tidal/.cache-size` and `.spotify/.cache-size`, holding `<MB>M` (`2048M`), librespot's `--cache-size-limit` form; the folder is made if missing and the file written with `blob_io` (a `.tmp`, synced and renamed). `stream_cache` reads it back with `state_read`; missing, or anything but those five sizes, is 2 GB. Files, not `config.ini`: `trim` reads Tidal's on the download thread, and the card's Spotify launcher reads Spotify's. The dot keeps Tidal's out of `trim`'s count and `cached`'s matches, and Tidal Downloads lists only songs. A smaller Tidal cap applies at the next download's `trim`. The launcher (q2-librespot's `contrib/shanlingq2/launcher.sh`) reads `.cache-size` before each librespot start, falling back to `2G` when it is empty or not digits with at most one trailing `K`, `M` or `G`, so a new Spotify size applies when librespot next starts. Older launchers ignore the file and keep `2G`.

**Stop Streaming Services** (`sc_click`) runs `spot_stop` (`SPOT_KILL`: the restart loop, librespot and its `aplay`, the state and `SPOT_OUT` files; `sp` cleared, so `spot_poll` idles, `spot_status` is 0 and the keys and `media_owner` are local music's), `radio_stop` (q2video `-r` quit or killed, `rd.active` 0) and, when the queue is a stock stream (`MCL_TYPE` neither 1 nor `0xf0xx`: Tidal) and hciplayer isn't stopped, `player_stop`. A local queue is left as it is; the next local track readies the DAC itself (`player_start`). It toasts "Streaming stopped" and is harmless with nothing running. Without it, a paused librespot stays the active source (`sp.active`) until a local track plays or `SPOT_IDLE_MS` passes, so Play/Pause, the side buttons, Bluetooth controls and the status bar follow Spotify, and a phone that casts again stops local music (`spot_take`). ponytail: AirPlay's receiver keeps running; its switch is on Network service.

Checks in `test/patch.py`: the row and its icon, the page's labels, each cache row's step, wrap and file, `stream_cache` on a size not in the list, every payload list page on the wheel's allowlist, and the stop row's kill, `player_stop` for a stream queue, its toast, and radio and Spotify no longer owning the keys.

## Album artists

Stock has two artist settings. `artist_type` (`0xa38acc`, `PLAYSET ARTISTTYPE`, read by `read_artistype_value`) is the artist page's own switch (`btn_artistswitch`), which picks its albums and songs by album artist (`getAlbumByAlbumArtist`, `getMusicByAlbumAndAlbumSonger`) or by artist. `g_artist_type` (`0xa38ae4`) picks `GetAllAlbumArtist` for the Artists list and the album-artist queries for an artist's albums in `load_localclass_list`, but nothing in stock writes it, so Artists always grouped by the Artist tag and a guest artist split an album. `ringnav_localclass` copies `artist_type` into `g_artist_type` before every list load, so Artists, an artist's albums, the artist page and the [Queue menu](#queue-menu) follow one setting. `GetAllAlbumArtist`'s row callback (`0x4fbc28`) fills the name at `+0x18` as `getAllArtist`'s does, and also at `+0x24`, so the rows show and expand the same way. **Audio settings → Artists** (`ringnav_audioset`, after stock's 15 rows in `scroll_view_playset`) toggles `artist_type` and writes `PLAYSET ARTISTTYPE`, as the artist page's switch does; the lists take it on their next load. Album Artist is the default: stock's read, `read_artistype_value` (`0x4f4724`, `atoi` of the key with `"0"` as its default), is replaced by `ringnav_read_artistype`, which reads a missing key as 1. Stock calls it only from `localmusic_localclass_page_init` and `localmusic_artistinfo_page_init`, so until a Library list or artist page opened, `artist_type` stayed 0 for Audio settings' row, boot resume (`memeory_startplayer`) and an artist page opened from Coverflow; `ringnav_bootmode` (`config_init`'s play-mode call, before Home restores the queue) reads it once at boot as well. Stock's `config.ini` template has no `ARTISTTYPE`, and only the two toggles write it, so a saved Artist (0) stays Artist. Stock's album-artist queries (`GetAllAlbumArtist`'s `group by albumsonger`, an artist's albums' and songs' `albumsonger like '%s'` and `albumsonger=""`, search) only match the tag, so in Album Artist mode an album without one was missing from its artist and listed under Unknown Artist. `ringnav_library_query` (the `toolsQueryDbTable` hook) rewrites every `albumsonger` in those queries to `ifnull(nullif(albumsonger,''),songer)`, as `ringnav_content_query` does on `toolsQueryContentDbTable` (`0x5c863c`, the same with a row argument and the name sort on the stack), which an artist's albums (`getAlbumByAlbumArtist`) run through, so such a song goes by its artist on both tabs; Unknown Artist keeps only songs with neither tag, its albums as its songs. `select *` records keep the real tag at `+0x24`, and Coverflow's own grouping (`ALBUM_SQL`, recognised by its `ifnull(albumsonger`) is left as is, so an untagged compilation stays one album there. Stock's libtag reads a Vorbis album artist only as `ALBUMARTIST`, so FLACs tagged `ALBUM ARTIST` (foobar2000's spelling) had an empty `albumsonger` and listed under Unknown Artist. `toolsGetMusicInfo` (`0x5c5f40`, called by the library scan, `player_get_id3info` and `get_songid3_info`) is hooked: when stock leaves its album artist (`info + 0x580`, `MUSIC_INFO_ALBUM_ARTIST`) empty, `ringnav_music_info` reads a `.flac`'s VORBIS_COMMENT block itself, seeking past the other metadata blocks, and copies `ALBUM ARTIST`, at most 255 bytes. Ogg Vorbis and Opus are not read.

**Artists rows.** Library Artists, Composers and Genres share one row template (built at `0x4b0efc`, bound at `0x4b0bc0`); each bind calls `0x4afc14` (`class_icon`), which sets `img_icon` to `default_artist_small` for Artists, a genre icon for Genres, or a `.downpic` picture. ## Charge Limit

The charger is the AXP2101 PMIC's integrated one (the device tree's `x-powers,axp2101-power-supply`, driven by `drivers/power/supply/axp2101_charger.c`, which registers `battery` and `axp2101_charger`; there is no bq25890 driver in the kernel or rootfs), set to 1000 mA of charge current, the 2000 mA USB input limit (`pmu_usbpc_cur`), a 4.35 V target (`pmu_init_chgvol` 0x10fe) and 100 mA of termination (`pmu_iterm_limit` 0x64). The fuel gauge is the CW2015 on I2C-0 (`/sys/devices/i2c-0/0-0062/cw2015_capacity`, `module_driver/cw2015.sh`). `toolsGetChargeStatus` (`0x5bca7c`) reads `/sys/class/power_supply/battery/status` (1 Charging, 2 Full, -1 Discharging or anything else, 0 unreadable); the `bq25890_1_status` paths it probes and the `echo %d > .../bq25890_1_otg_enable` helper are for the other Shanling players that share `demo`. `switch_charge_enable(on)` (`0x4f3cfc`) sets the active-low charge enable on GPIO `PE22` through `toolsGpioSetValue` (libgpio, no shell); stock uses it only for USB mode's and AirPlay's charge choice (`g_usbdac_chargeflag`; `usbmode_page_init`, `usbmode_exit`, `airplay_page_init`). With it high, charging is off and the player runs from USB while the battery holds. `get_battery_capacity` (`0x4f4afc`) keeps `g_power_capacity` (0-100) and `g_power_chargestate` (a negative status is not stored).

**System settings → Power → Charge Limit** (`ringnav_powermanager`, after stock's rows in `scroll_view_powermanager`; `Q2POD CHARGELIMIT` in `config.ini`). Every `CHARGE_POLL_MS` (5 s) `charge_poll`, from `ringnav_sleep`, stops charging at `CHARGE_STOP` (80%), stops it again if anything turned it back on meanwhile (USB mode's exit, AirPlay) while the charger reports charging, and hands it back at `CHARGE_RESUME` (75%) or when the limit is turned off: on, or `g_usbdac_chargeflag` while `usbmode_page` or `airplay_page` is open. ponytail: only while demo runs; a powered-off Q2 charges as stock.

## Low Power

**System settings → Power → Low Power** (`Q2POD LOWPOWER`). The kernel (5.10, SMP) has CPU hotplug but no cpufreq core, so the clock cannot be lowered; Low Power saves where it can without touching what you hear or see. While the screen is off and no video plays, CPU1 goes offline (`/sys/devices/system/cpu/cpu1/online`); the player decodes on one core, which plain playback, PEQ included, does not need two for. With the screen on, both cores are up, so Coverflow's software renderer and the UI never compete with hciplayer (`nice -5`, not real-time). The first offline of a boot is bracketed by `/mnt/data/q2pod-cpu1`: written and `fsync`ed before, unlinked and the directory `fsync`ed after. If a kernel stalled on it, the next boot finds the file, renames it `.bad` and never tries again (delete it to try again); a marker that cannot be synced means no offline that boot. An offline the kernel refuses stops the attempts until the next boot; a refused online is retried once a second. Off, no file is touched.

## Coverflow sort

The **Sort** card, just before **Refresh library**, cycles **Album** (stock order), **Artist**, **Year**, **Recently Added**, **Most Played** and **Random**, saved in `/mnt/data/ringnav-coversort` (an int, through `blob_io`, so Refresh keeps it). The stock album list is still queried and kept as before (`cf.stock`); the shown list is a sorted copy of it. Artist, Year and Recently Added rank albums by `toolsQueryDbTable(db, sql, row, 0)` with `split_row` over Coverflow's `ALBUM_SQL` grouping with an `ORDER BY`: `ifnull(max(year),0)=0, max(year), album` (oldest first) or the same with `max(year) desc` (newest first) for Artist's year order and Year, as Playback settings' **Year Order** (Q2POD `YEAROLD`, `ringnav_year_old`; a change re-sorts on the next open), undated last, and `max(time_create) desc` for Recently Added (the 0 skips stock's name sort, `0x5c8120`). ## Hold Return

**Display → Hold Return: Home** (`Q2POD HOLDRETURN`, [ipod.md](ipod.md#hold-return)) sends a hold to stock `navigator_back_to_home`, which closes windows and opens none: with a modal dialog on top it calls `dialog_quit` and goes on once the dialog is destroyed, otherwise it closes the stack from an idle. ## Play counts

The Resume poll also counts listens, for every track but [Podcasts and Audiobooks](#podcasts-and-audiobooks). It adds the seconds heard: a step of 1 or 2 s between polls, so seeks, pauses and Resume's jump add nothing. Once a track longer than `LISTEN_MIN_S` (30 s) has had half its length, or `LISTEN_MAX_S` (4 minutes), heard, its path's FNV-1a hash (with a CUE track's start mixed in, as a CUE image's tracks share one path) is counted, once per play; a new key (another track, or another CUE track of the same image) or the time falling back under 2 s from past 30 s (repeat one, or a seek to the start) starts a new play. The counts are a fixed table of `PLAYS_SLOTS` (512) hash/count pairs, 4 KB, in `/mnt/data/ringnav-plays`, read on first use and written whole like Resume's ring. A counted track moves first; with no free slot, the furthest back of the lowest counts, the least recently played, is replaced. The file never grows, whatever the library's size. Keys are paths, so counts survive Update Local Music and a moved or renamed file starts again from zero.

**Most Played** (Local Music, under Shuffle) runs `getAllMusic` through `staged` as Shuffle Songs does, looks each song's path hash up in the table and lists the top `PLAYS_TOP` (100) on a runtime `mostplayed_page` (`page_list`, as Books', in 64 px `page_row_detail` rows: the title over "Artist · N plays", or the count alone when untagged, in 16 px `#AAAAAA`, stock's `s_scrlabel_gray24l` grey), most played first and, among equal counts, the most recently counted first (the table's order). A row folder-plays that ranked `stSongInfo` deque from itself and leaves the play mode alone. A Play/Pause hold opens the song menu over the same deque, as on Coverflow's tracks; for that the page is `CTX_FIXED`, so it also comes back on the last row. Nothing counted titles the page "No plays yet". The ranked deque is kept after the page closes, and a song counted while it is closed that is not in it is appended (up to 2 × `PLAYS_TOP`), so a later open ranks only those, not the library. The library is read again after Coverflow's `library_gen` moves (scan or delete), when the deque would grow past that or such a song is counted with the page open, or when a full table drops the count of a song in it, since the next best could be any song. A song first counted from stock's folder browser has that queue's record, without library tags, until then.

## Ratings

A song has 0 to 5 hearts. Five is stock's My Fav (the `myfav` table, `checkFavExist`), so Now Playing's heart, the queue menu's Favourites rows and the Loved list stay one value; 1 to 4 are kept in `/mnt/data/ringnav-ratings`, `RATE_SLOTS` (4096) words, each a song's `listen_key` (the [play counts](#play-counts)' path hash) with its low three bits replaced by the hearts, 0 for a free slot. The table is `calloc`'d and read whole on first use and written whole through `blob_io` on each change; a full table refuses a new rating with a toast rather than drop one.

**Now Playing.** `playing_page_init` is hooked in both builds (`ringnav_playing`; Legacy's does only this). Stock binds `img_fav`'s click to `0x52b154` with the window as context: for a local track it runs `manage_myfav` (`0x516cd8`, My Fav toggled for the queue's playing index) and swaps the heart's image. `rate_bind` finds that binding in the heart's emitter, takes it off and binds its own click and `EVT_POINTER_DOWN`. A press arms `RATE_HOLD_MS` (500 ms); if the pointer is still down then, the picker opens, sends the window `EVT_POINTER_ABORT` (as pull-to-search does) so the `slide_view` under the finger lets go and cannot drag pages behind the picker, and the release's click is dropped. The heart's click returns 0, as stock's does: after a child's STOP stock's `widget_on_pointer_up` skips the parents' own release, so the `slide_view` kept the window's grab, and the seek bar and More took no taps until the page closed. The queue menu's "Queue unchanged" pick returns 0 for the same reason (its list's `scroll_view`). A tap runs stock's click and then clears any 1-4 kept for the track, so a heart taken away leaves the song unrated. A label on the heart's top right shows a kept 1-4 while the heart is empty (`play_unfav`), refreshed every 500 ms with the screen on; it is insensitive, so the heart takes the taps under it.

**Picker.** A `LETTER_ALPHA` rounded panel in the stock dark surface, built once per page over its centre, holds a caption ("N of 5", "Unrated") and five 56 px images of the heart's own `play_fav` and `play_unfav`. While it shows, `ringnav` sends it the wheel (±1 within 0-5), Centre (save) and Return (close unsaved), ahead of stock and the page's own keys; tapping heart _k_ saves _k_. Closing hides the panel and makes it insensitive: stock's `widget_find_target_default` (`0x669c6c`) skips only children without enable and sensitive (flags `0x9`), not hidden ones, so a hidden panel would keep taking every touch over the cover until the page was left. Saving keeps 1-4 or nothing, and calls the heart's stock click when My Fav has to change (5 in, anything else out). **Hold Play/Pause** on local Now Playing puts **Rate** first in the queue menu, with the hearts, opening the same picker (`QA_RATE`).

**Lists.** Library's **Ratings** row (`library_into`, stock's `local_fav` icon) takes My Fav's place, whose stock row stays hidden next to it. It opens `ratings_page` with Top Rated (4-5), Loved (5), All Rated (1-5) and Disliked (1). Each runs `getAllMusic(0)` (title order) and `getAllFav` (`0x4fef24`, `select * from myfav` through the same row callback, `0x4fb8b8`) through `staged`, rates every song against the fav keys and the kept ones, and lists the matches most hearts first on `rated_page`, as Most Played's: "♥♥♥♡♡ · Artist" under the title, a row playing the list from itself as a library queue, the queue menu on a Play/Pause hold (`CTX_FIXED`). ponytail: every song against every rated one; fine for thousands rated, a sorted table if not.

**Albums.** An album has its own 0 to 5 hearts in `/mnt/data/ringnav-album-ratings`, the same `RATE_SLOTS` word table (5 included, an album having no stock favourite), keyed by `album_id` (coverflow.c): an FNV-1a hash of what `album_cmp` compares, the name and album artist ASCII-lowercased, else the name and the album folder (`album_dir`, disc folders as one, case kept); the Unknown Album card is one album. A slot whose hearts read 6 or 7 counts as unrated, and a short file reads as empty. A save writes the table whole; a failed write puts the slot back and toasts "Rating not saved", a full table "Ratings are full". The queue menu gives an album **Add/Remove from Favourites** (5 or 0) and **Rate Album** with its hearts (`qm_album_id`): a Coverflow cover's record, a Library Albums row (split as Coverflow's), or an artist's albums tab row, whose split album `ringnav_artist_list` finds as for art keys and keeps in `art_ids`. Rate Album opens the picker over that page (`rate_panel`, found by name, so Now Playing's and Coverflow's each have one); saving runs `qm_record` again and saves nothing ("Album changed") unless the page is still top with the same row or centred cover. The picker's state clears with its panel or page. A Play/Pause hold while it is up is latched and ignored. **Ratings → Albums** (after Loved) is `coverflow_rated`: `getAllAlbum`, `split`, the albums with hearts, on a Coverflow page scoped as an artist's (`RATED_ALBUMS`: no saved album, no Refresh, Return goes back) whose one card sorts by Rating (most first), Album (library order), Artist or Year (as Year Order, undated last), kept in `/mnt/data/ringnav-ratedsort`; the library's albums and Sort come back on close.

## Long Songs

Stock's `songtable` has no length: its `time` and `time_end` are a CUE track's start and end seconds (`REC_CUE_START`, `REC_CUE_END`). **Long Songs** (Library, after Hi-Res, `local_longsongs`, a copy of stock's `system_time`) therefore measures files itself, once. A CUE track with both ends takes `end - start`; any other song takes its file's length, less a CUE start, from `/mnt/data/ringnav-lengths`: `{FNV-1a path hash, seconds}` pairs sorted by hash, read whole on first use and searched by bisection. The files not in it are probed on a pthread (`ls_worker`) with the TagLib demo already links: `taglib_file_new`, `taglib_file_audioproperties`, then `AudioProperties::length()` through its vtable (`+0xc`), as libtag_c's `taglib_audioproperties_length` calls it (demo imports no `taglib_audioproperties_length`); an unreadable file is kept as 0 seconds so it isn't probed again. While it runs, the page counts ("Measuring songs… n/N", a 250 ms poll) over a Cancel row; finishing, Cancel or closing the page joins the worker and merges what was probed into the table, which is written whole through `blob_io`. Then `longsongs_page` lists every song over `LONG_SONG_S` (600 s), longest first, "Artist · length" under the title, as Most Played's: a row plays the list from itself as a library queue, and a Play/Pause hold opens the song menu (`CTX_FIXED`, the list in `rt_list`). ponytail: a file edited in place keeps its first length, and removed files' entries stay; the table is a few bytes a song.

## Scrobbling

The same listen also appends a line to `/mnt/mmc/.scrobbler.log`, the card's root, in Rockbox's AudioScrobbler portable-player 1.1 format, so any `.scrobbler.log` uploader can send it to Last.fm or ListenBrainz. A missing file (`access`) gets the `#AUDIOSCROBBLER/1.1`, `#TZ/UTC` and `#CLIENT/Q2 Pod` header first. Each line is artist, album, title, track number, the length in seconds, `L` (listened), the start time and an empty MusicBrainz ID, tab-separated, from the record's `REC_ARTIST`, `REC_ALBUM`, `REC_TITLE` (the tag's; without one, `REC_NAME`, the file name, less its extension) and `REC_TRACK` (left empty when 0); tabs and newlines in tags become spaces. The start time is `time()` less the seconds heard, UTC since the clock fix keeps the system clock in UTC. Artist and album are the player's parsed tags once it has parsed the track (`now_tag`, see [Now Playing](#now-playing-ipod)), so a next folder's untagged records still log. A track with no artist, or a listen while the clock reads before 2020 (never set), is not logged, as scrobblers reject both. With `[SCROBBLE] ALBUM_ARTIST=1` in `.scrobble.ini` (`scrobble_album_artist`, read at each listen), the artist column is the album artist instead, when the song has one: the player's parsed one (`ID3_ALBUM_ARTIST`, `g_play_id3_info + 0x984`, which `player_get_id3info` fills through `toolsGetMusicInfo` for every non-CUE track), else the record's (`REC_ALBUM_ARTIST`, `+0x24` `albumsonger`, which the song row callback `0x4fb8b8` fills for library rows; folder-queue records have none, and the player copies none for a CUE track). The log stays in the 1.1 format, so any uploader sends the same artist. The file is only appended to, about 100 bytes a listen, by `scrobble_append` in `patch/scrobble.c` under the upload's lock.

**Upload Scrobbles** (Local Music, index 2, after Most Played, with a build-added copy of stock's 52 px `wifiset_wifi` as `local_scrobble`) is created only when `/mnt/mmc/.scrobble.ini`, read with `toolsReadConfig`, has `[LISTENBRAINZ] TOKEN` or all four of `[LASTFM] USER`, `PASSWORD`, `API_KEY` and `API_SECRET`. A press with `get_wifisignal` (`0x50e428`, the status bar's bars, -1 unless connected) at 0 or below says "Connect to Wi-Fi first". Otherwise `scrobble_start` reads the accounts again and starts one pthread, and a 500 ms timer (`upload_wait`) polls it and joins it, then toasts the count sent, "Nothing to upload" or "Upload failed, N sent". The thread reads the log, takes complete lines in batches of 50 (Last.fm's limit) and skips comments, lines not rated `L` and lines without artist, title or time. It sends a batch through demo's own libcurl imports: ListenBrainz `submit-listens` as `import` JSON with `Authorization: Token`, and Last.fm `track.scrobble`, form-encoded and signed (`api_sig`, the MD5, from demo's libcrypto `MD5_*` imports, of the sorted names and values followed by the secret), with a session key from `auth.getMobileSession` fetched once per upload, before the first batch. A batch counts as sent only when every configured service answered 200 (and Last.fm's reply has no `error`). The first failure stops the upload. A service that took a batch the other refused gets it again next time. Then, under the lock, the bytes of every sent batch go to `.scrobbler.log.sent` (comments dropped) and the log is rewritten, to a `.tmp` then renamed, as the header plus what follows them. Listens appended during the upload are therefore kept. Uploads always enable `SSL_VERIFYPEER` and `SSL_VERIFYHOST`; `/etc/scrobble-ca.pem`, packaged in the firmware, supplies `CAINFO` because stock has no CA bundle; no certificate file is required on the card. It contains the ListenBrainz and Last.fm trust roots from [Mozilla’s CA store converted by curl](https://curl.se/docs/caextract.html) (MPL-2.0), checked against both services when updated. Archive writes must flush and sync successfully before pending listens are removed, and storage failures are reported to the UI.

## Battery

The kernel has no cpufreq core (no governor to set) and stays stock; five rootfs drains change instead.

PEQ's steady bypass skips its sample loop; the filter still requests float PCM, so bypass doesn't remove every format conversion in the player. ponytail: the format is picked once per track, at the filter's `af_reinit` (`control(0x10000100)`, from `af_add` at each file load); nothing on our side reinits mid-track, so a native-PCM bypass would leave EQ, the visualizer and the outgoing crossfade dead until the next track. Native bypass needs a mid-track reinit (re-sending stock's EQ-on, unverified) or int PCM converted in `play()` (needs the vendor's format codes and stock's rounding); the filter is only in the chain once EQ, Crossfade or the visualizer has been used.

- **drop_caches.** `check_mem_thd` (`0x512050`, started by `platform_init`) writes `3` to `/proc/sys/vm/drop_caches` every sixth second for the life of the player, throwing away the page, dentry and inode caches: the library database, the card's directories, the playing file's readahead and squashfs assets are read again. `toolsGetSysMemFree` has no callers, so nothing depends on it. Its first two words become `jr $ra; move $v0,$zero` (`DROP_CACHES` in `tools/build.py`), so the thread exits as soon as it starts: no write, and no one-second wake. `platform_init` detaches it and nothing joins it.
- **UI loop.** `main_loop_sleep_default` sleeps at most 8 ms (its expected-sleep argument can only shorten that), so AWTK's loop runs at 125 Hz, screen on or off. `ringnav_sleep` first sleeps `SCREEN_OFF_SLEEP_MS` (100 ms, `patch/offsets.inc`) with `sleep_ms` (`0x724928`) while `g_backlight_status` is clear; stock then finds its 8 ms gone, sleeps 0 and updates its own timestamps. The loop runs at about 10 Hz with the screen off, and a key pressed then waits at most 100 ms longer. Once nothing plays (`media_playing`: local, Spotify, radio or video; no AirPlay or Bluetooth receiver) and `check_dacoff_state` has powered the DAC off (`g_dacoff_time` -1, about 31 s after playback stops), it sleeps `DARK_IDLE_SLEEP_MS` (250 ms) instead, about 4 passes a second: a Q2 left dark without Standby otherwise keeps waking both cores for nothing. The first key then waits at most 250 ms; for `WAKE_MS` after a dropped Wake press the pass stays at 100 ms, so the second press is timed as before. With the screen on, once `IDLE_MS` (2 s) pass without input (`ringnav_input` times every event) or a window animation, each pass idles `IDLE_SLEEP_MS` (25 ms), about 30 a second instead of 125; the first input wakes it within that. Now Playing (`playing_page` on top) keeps stock's pace only while its visualizer repaints (`visualizer_live`) or its album marquee moves, whose 40 and 50 ms timers an idle pass would make late; its 250 ms progress and lyrics keep up. The first pass with the backlight back on calls `widget_invalidate_force` on the window manager once, so the whole screen repaints on wake rather than only the regions that change next.
- **Painting.** Stock's screen-off (`screen_action`, `0x4f77d4`, with 0) turns the backlight off and blanks the framebuffer (`disable_fb`, `0x4f3bcc`), but nothing in the UI loop reads `g_backlight_status`: `main_loop_simple`'s step paints every pass (`window_manager_paint` at `0x68b278`), and Now Playing's 250 ms timer (`0x52bffc`) runs its page update (`0x52b6f4`) whatever the screen. So a Q2 left dark on Now Playing kept drawing its times and bar into a blanked framebuffer. `ringnav_wm_paint` returns `RET_OK` without painting while the backlight is off, unless a window animation runs (`window_manager_is_animating`): AWTK steps it from the paint, so it would otherwise wait for the screen. Invalidated regions keep, and the first lit pass repaints the whole screen as above.
- **MQA side chain.** hciplayer ran every probed FLAC and PCM stream through the MQA decoder; the build runs it only for MQA ([MQA detection](#mqa-detection)).
- **Watchdog.** `platform_init` starts `checkappprocess.sh`, which forks `pgrep` every 2 s and reboots if `demo` is gone. Its `sleep 2` becomes `sleep 10` (`WATCHDOG` in `tools/build.py`), so a crashed player reboots within 10 s.

## ALSA startup lock

The stock ALSA 1.1.6 library can deadlock with an ioplug behind `plug`. Preparation locks the wrapper while the ioplug callback unlocks and relocks its slave, leaving a slave mutex owned by the setup thread, so the writer blocks at its first write. `q2video` sets `LIBASOUND_THREAD_SAFE=0` in its own process before opening ALSA. Its PCM calls are sequential: setup precedes the writer, and drop, prepare and close follow joining it. BlueALSA's locks, the local player, the codecs and the services are unchanged.

To reproduce the old hang and verify the fix against the stock MIPS library, run `python3 test/alsa.py BUILD QEMU_MIPSEL`. The regression covers one and two plug layers and rate conversion.

## Audio writes and the queue checkpoint

The shared audio writer keeps partial ALSA writes and retries the remaining frames after an underrun, instead of discarding unwritten samples. Native tests exercise partial writes, zero progress, recovery and lost outputs. This is independent of the ALSA startup lock workaround.

Queue and traversal changes commit the full queue snapshot, for queues up to `SAVE_LIMIT` (999) tracks; a larger one keeps no snapshot (it would be rewritten whole on every track change), so a reboot resumes it as stock does. Elapsed-only changes atomically replace the 16-byte `ringnav-queue-elapsed` checkpoint, which applies only when it matches the snapshot's checksum and position.

## M4B recognition and audit

Stock has two audio extension checks: folder enumeration at `0x5c2054` and recursive scanning at `0x5c3da4`. Both also feed playlist loading. `ringnav_audio_extension` accepts `.m4b` case-insensitively and otherwise calls the original `strstr` with its original format list. The builder asserts the original import load and call bytes before replacing each call; `audio_extension_calls` records both edits in the manifest and packaging audit. The installed TagLib already sends M4B to the MP4 constructor, and the decoder probes the original MP4 container. Neither needs a binary dispatch change. Cover extraction has a separate extension dispatcher in `libtag_c.so.2.0.1`, which stock recognizes as MP4 artwork only for M4A/MP4. `patch_m4b_cover` in `tools/build.py` checks the whole library hash and adds a case-insensitive M4B comparison that reaches the existing MP4 image extractor. Its 48-byte appended segment is read/execute only, uses relative branches and GP-relative data, and preserves the other formats. Now Playing retains stock’s external folder-cover fallback when embedded extraction fails; Coverflow retains its folder-image fallback. Files and paths are preserved. `test/m4b.py` executes the native metadata and cover dispatchers at two load addresses, while `test/patch.py` covers the patched checks, short-book persistence and shared resume/count exclusions.

## Headset controls and volume

`patch/headset.c` restores the AACP handshake and AVRCP input from `6799d59`, without the battery state or connection card. One generation-tagged worker uses nonblocking socket/input I/O and bounded `select` waits. It drains the AACP socket each pass (AirPods send other reports between ear reports), validates complete ear packets, retries discovery throughout a connection, queues only key presses, and closes descriptors on disconnect. The UI loop discards stale generations and dispatches commands every 100 ms. No player API runs on the worker.

The internal dispatcher chooses video, radio, Spotify, then the stock local/Tidal player, independently of the visible page. Explicit play/pause operations and session identities support ear detection; the number of buds originally worn (counted, since the report's primary/secondary slots swap when the primary leaves an ear), a manual-command epoch and the player/session identity gate automatic resume. Recent AVRCP pauses are coordinated with ear reports, and duplicate commands are suppressed. Player starts, track changes, manual controls and disconnects invalidate pending resume. Video retains its commands and adds idempotent `a`/`r` pause/resume, an atomic pause-state file and a separate `g` gain command. Radio resumes the current station by restarting it.

Volume starts by writing the Q2's saved volume to the headset, unless the headset's level already reads as it (128 headset steps map onto 101, so a step that rounds to the same volume is left alone). Polling then consumes headset changes, rounds between 0–127 and 0–100, enforces the configured limit, saves Q2 state and updates the visible volume slider. Remembering the accepted absolute value prevents feedback loops. Confirmed headset volume uses full helper gain except at zero; unsupported or failed reads/writes restore software gain. Spotify, radio and video consume the same effective gain. The AAC 48 kHz capability fix remains in place.

`test/patch.py`'s headset cases run routing, ear counts and slot swaps, single-bud listening, first reports, manual cancellation, player/session changes, duplicate commands, malformed reports and volume limits against the MIPS payload. `test/headset_io.py` runs the actual worker with simulated kernel I/O, including late input discovery, handshake, draining queued reports, release/repeat filtering, cleanup and stale reconnect reports.

## Resume on Connect

Two paths start playback when a headset connects. Stock's `checkBluetoothStatus` (`0x4f2cfc`), once a headset's A2DP comes up with the Q2 as the source, runs `player_save_stop` (saves `mclGetPlayStatus` unless stopped, then `mclStop`), `config_outputchannel(2, 3)`, `device_set_volume` and `player_save_start(0)` (`0x4f358c`). That restarts the saved local or Tidal queue unpaused, so a paused queue plays, and a stopped queue with a stale saved status starts over Spotify or Internet Radio (`mclStartPlayer`'s hook yields them). AirPods also send AVRCP PLAY as the link comes up, which `headset_command` turns into a start for whichever player is active.

**Bluetooth → Resume on Connect** (`ringnav_btrows`, hooking stock's list builder `0x4bee90`, which rebuilds the whole list on every search and link change; `Q2POD RESUME` in `config.ini`; On, 1, is stock's behaviour) is Off by default. With Bluetooth on, the row goes right after stock's fourth row, Bluetooth Headset Volume Control (`bt_adjvol`, before Scan now), text only and 78 high like stock's rows; with Bluetooth off (just the switch) it isn't added. The jalr at `0x4f358c` becomes `jal ringnav_bt_connect_start`, which with the setting On calls `player_save_start(0)` as stock; Off, it lets a playing queue go on, reloads a paused one paused (`player_save_start(1)`, as stock's disconnect does) and starts nothing for a stopped queue or while a stream owns playback. Off, `headset_command` also drops PLAY (200, 207, or 164 while nothing plays) within `CONNECT_HOLD_MS` (5 s) of the link, which covers the worker's AVRCP discovery (about a second) and the headset's PLAY after A2DP setup; a press after that plays. Ear detection is a separate path: the first ear report after a connect never resumes, and putting worn buds back resumes only what removing them paused, with the setting either way. AirPlay and DLNA keep their senders' control (stock skips the restart while AirPlay plays).

## Wi-Fi transfer

Stock's Wi-Fi transfer page (thttpd on port 8888, `/usr/share/web`: `index.html`, `js/index.js` on jQuery File Upload 5.40.1 and five CGIs) is patched in place by `patch_web` (`WEB` in `tools/build.py`: exact replacements, each checked against the audited stock file, and no Chinese may be left). Every string is in English. The extension filter (client-side only; `upload.cgi` takes any file) adds the formats Q2 Pod's pages read: M4B, MP4, M4V, MKV, AVI, MOV, MPG, TXT and EPUB.

**Folders.** **Upload Folder** is a second file input with `webkitdirectory`, sharing the upload widget (`fileInput`). A picked folder's files carry `webkitRelativePath` (`Album/CD1/01.flac`), a dropped folder's (the plugin walks it; patched to call `readEntries` until it returns none, as Chromium gives at most 100 entries a call) `relativePath` (`Album/CD1/`); either way the file goes to the current folder plus that path, and its dot files (`.DS_Store`, macOS's `._` copies) are skipped silently. Stock's `upload.cgi` only moves the part into `path` (`mv "%s" "%s" -f`), so `_mkdir` first makes each folder with stock's `create` (`mkdir "%s"`, no `-p`), parents first, once per batch (`_made`, cleared when the batch stops): one that exists fails harmlessly, and a folder that really couldn't be made shows as its files' upload errors. A file's row shows the upload panel as it is added and can be cancelled while its folders are made; the panel hides (and `_made` clears) only once no row is left, since the plugin's `stop` fires whenever no upload is in flight, also between files that wait on a folder. ponytail: the stock CGIs run `mkdir` and `mv` through `system()` inside double quotes, so a name holding `"`, `` ` `` or `$` can't be uploaded, as a plain file can't on stock; replacing the CGIs would lift it.

Checks in `test/build.py`: the three files in the image are `patch_web` of stock's, listed in the manifest's changed assets.
